# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

eXPoSe SpectraDeck: a single-window Tkinter app that browses, plots and exports XPS spectra from many instruments — Kratos ESCApe (`.experiment`) and Vision (`.kal`), VAMAS (any vendor), Thermo Avantage (`.avg`/`.vgd`/`.avx`), PHI MultiPak (`.spe`), Scienta SES (`.txt`) — to CSV or VAMAS. See `README.md` for the user-facing tour.

## Commands

```bash
python launch.py                # create ./.venv, install deps, start the app (python3 on macOS/Linux)
python launch.py --setup-only   # build the venv without starting the app
python launch.py --reinstall    # rebuild the venv from scratch
python launch.py --check        # report venv / tkinter / app-file status
python spectradeck.py       # run directly with the current interpreter
python -m unittest discover tests            # unit tests (synthetic files, no instrument data needed; includes palette contrast/separation and colour-rule tests)
XPS_CORPUS=<folder> python -m unittest tests.test_corpus   # every recognised file in a folder must load
```

There is no linter or build step. Dependencies (`matplotlib`, `pillow`, `reportlab`, `pymupdf`) are in `requirements.txt`; `launch.py` keeps a `REQUIRED` fallback list that must stay in sync and re-installs when the requirements file's SHA-1 changes. `tkinter` comes from the base Python, not the venv. The app must still start when matplotlib / Pillow / PyMuPDF are missing (`HAVE_MPL`, `HAVE_PIL`, `pdf_preview.HAVE_PDF`).

## Architecture

`spectradeck.py` is the entry point (window, dialogs, `main()`); the application name lives in `appinfo.NAME` ("eXPoSe SpectraDeck", formerly "ESCApe Explorer" — use the constant, never a literal; `tests/test_appname.py` enforces it); everything else is a module beside it:

- **`readers/`** — one reader per format behind `readers.load_file(path)`. `readers/__init__.py` holds the `READERS` registry and picks a reader by **content sniffing** first (extension is only a hint), so renamed files still open; add a format by writing a `SpectrumFile` subclass with a `sniff(head, ext)` function and registering it there (this also feeds the Open dialog filters).
  - `readers/base.py`: `Region` / `TreeNode` / `ImageBlob` dataclasses and the `SpectrumFile` base class. A reader only fills `regions` (+ `instrument`, optional `depth_profile`, `_sample_pos`, `images`) and calls `_finish()`; the tree, per-region metadata and positions then come from the base class. Shared helpers: `canon_region_name` ("C1s" → "C 1s", surveys → "Survey", so the same core level groups across formats), `guess_region_name` (a "core level" on a >250 eV axis is a survey), `kv_from_lines`, `read_bytes` (always use it — never leave file handles open).
  - `Region.energy` is **binding energy** for XPS whenever the photon energy is known (BE = hν − KE, as CasaXPS does); otherwise the native axis is kept and `energy_label` says so (only "Binding…" axes are inverted when plotted).
  - `vamas.py`: field-by-field ISO 14976 parser. Header layout varies by experiment mode (e.g. `SDPSV` has no "number of spectral regions"), so `load()` tries the expected layout then alternatives; numbers between the source label and analyser mode are read by type because the count varies by mode; `IRREGULAR` scans have no start/step (the first corresponding variable is the abscissa).
  - `thermo_avg.py` defines `DataSpace` and `ThermoDataSpaceFile._from_dataspace`, shared with `thermo_vgd.py` (pure-Python OLE2 in `ole2.py`, no `olefile`). `.vgd` property ids → `DS_*` names are the `PID_NAMES` table; the axis stream is decoded by anchoring on the expected item counts, and the **axis type code** is the int32 right after each axis's linear flag (1 ENERGY, 3 X, 4 Y, 6 ETCHLEVEL, 8 ETCHTIME, 10 POSITION: `AXIS_CODES`). `dataspace_kind(ds)` classifies a DataSpace as `spectrum` / `position` (one spectrum per analysis point) / `levels` (depth profile; etch time from the ETCHTIME axis) / `map` (SnapMap) / `image` (camera picture: value type 13, one packed **B<<16|G<<8|R** float per pixel, checked pixel for pixel against Avantage's PNG export; the `.vgd` reader leaves `VGData` unread and the PNG is made by `ImageBlob.loader` on demand) / `table` (auto-height Z values: `value_table`, no regions; the `.avg` dump does not list per-point X/Y there) / `other`. Both readers must stay identical on every pair (validated on 146 `.vgd`/`.avg` pairs). A DataSpace with no axes raises "this DataSpace is empty" (an aborted acquisition). A SnapMap `.vgd` is handed over as raw doubles (`DataSpace.raw`, ~0.1 s) rather than per-pixel lists.
  - `thermo_vgx.py` parses an Avantage `.VGX` (OLE2 of MFC objects; only the `FF FE FF`-prefixed UTF-16 strings are read): experiment / project / platter / date folder from the root, then group (source configuration, e.g. "X-Ray005 200um - FG  ON") → sample → step nodes ordered by their `Embedding N` numbers (= run order). A sample node's own strings list its scans differently per scan type, so they are only matched against folder names. `thermo_experiment.ThermoExperiment` opens a **folder or a `.VGX`** as one `SpectrumFile` (`readers.load_file(path, progress=)`; `looks_like_experiment`, `find_vgx` looks up to 4 levels above a folder): sample = the folder below the configuration, `Region.sample` = "<sample> <Pt #001a>" for multi-point scans, `.vgd` preferred over `.avg`, `errors` / `skipped` collected without stopping, `members` = every file used (for the workbook), custom `_build_tree` (experiment → `samplegroup` → `sample` → scans; depth-profile samples use `regionfolder` levels; duplicate core levels get the scan name). Camera images become `ImageBlob`s (`fmt="png"`, `calib`, `sample`, label time from the file name because stored times are UTC).
  - `phi_spe.py` (16-byte preamble, all 96-byte block headers, then float64 blocks; counts/s), `scienta_txt.py`, `kratos_kal.py`, `kratos_experiment.py` (the original reverse-engineered `EscapeParser`).
- **`snapmap.py`** / **`snapmap_ui.py`** — `MapCube` (float32 `array` `[iy][ix][channel]`, `x0/dx/y0/dy` in µm in the *image* frame, `stage_x_mm/stage_y_mm`), attached as `Region.extra["cube"]` beside the summed-spectrum region; numpy only inside `image` / `roi_spectrum` / `rect_mask` / `default_window` / `colour_range`. `default_window` takes a sloping baseline off, ignores the outer tenth, favours the middle and enforces ≥ 2 eV (weak Cu 2p peaks fooled simpler rules). `SnapMapDialog` (energy window by `SpanSelector`, ROI by `RectangleSelector`, element switch, overlay on the nearest camera image, PNG/CSV export) opens from Tools, the tree context menu or a double-click (`Workspace.open_snapmap`).
- **`snapshot.py`** — camera-image geometry from `ImageBlob.calib`: `stage_to_pixel` / `pixel_to_stage` / `markers` / `map_rectangle` / `nearest_image`. **Measured** on K-Alpha+ (registering neighbouring photos, r 0.53–0.80 vs < 0.3 for the other sign choices): image x runs *against* stage X, image y *with* stage Y (`X_DIR`, `Y_DIR`); a SnapMap's own axes follow the image (they overlay the photo without a flip) and are centred on its stage position. `Workspace._render_snapshot` draws it (used instead of the holder-photo overlay for calibrated images); thumbnails are filled one per `after` tick (`_fill_thumbs`). `view_of(calib, positions, sites)` returns the points and map outlines inside a picture (used by the HTML browser and the report pages).
- **`imagepages.py`** — camera pictures and SnapMaps as report pages and slides, Tk-free until drawn. `plan(docs, label_of, display, per_sheet, columns)` returns `Page`s (camera sheets first, then one per map site: `kind`, `title`, `n_items`, `draw(fig, rect, cmap)`, lazy `notes()`); `Picture.array()` shrinks to `PICTURE_PX`; the axes keep the full-size picture's pixel coordinates so marker geometry from `snapshot.view_of` is used unscaled; a map site is drawn as an outline (labelled) instead of a marker. `Workspace._image_page_plan/_render_image_pages` draw them under the print style (`_report_image_pages(pdf)` for `report.build_report(..., render_images=)`, `_deck_image_pages()` for `pptx_export.build_deck(..., image_pages=)`: 3 pictures per slide, camera slides as JPEG); sections `"images"` sit between metadata and figures in both, and are offered only when `_has_image_pages()`.
- **`viewdata.py`** — Tk-free helpers for the alternative views: `energy_axis` (BE ↔ KE per region; kinetic falls back to native when hν is unknown), `resolve_z` / `z_sorted` (z axis of waterfall/heatmap: etch time → level → acquisition time → trace order; all-zero etch times count as absent; acquisition date comes from `SpectrumFile.date_for_region`, because the Kratos `.experiment` reader leaves `Region.date` empty), `build_matrix` (resample onto one grid, NaN outside a trace's range).
- **`panelview.py`** — per-panel view overrides (Tk-free). The view row (view, normalise, offset, z axis, reverse, fit layers) is only the *page default*; a panel (keyed by its group label, so use a per-sample grouping to give two samples' C 1s different views) may override any of those keys in `Workspace.panel_views`, so one page can hold a waterfall, a stack and a fitted spectrum. `VIEWS` = Stack / Waterfall 3D / Heatmap / **Fit** (a stack of one trace with the CasaXPS fit forced on; `Workspace._panel_limit` makes its trace window 1, `_trace_span` sizes the trace slider from the panel whose window slides furthest, no stored fit → plain trace + note). `sanitise` / `sanitise_all` / `resolve` / `with_value` / `reset` / `arrange` (z order for series views, optional reverse for stacks) / `describe`. `Workspace._page_defaults` + `_look_for(key)` are the only readers of the view variables inside `_groups` / `_draw_page` / `_fit_overlay(show)` / click handlers; never read `view_var` etc. per panel directly. Edited by right-clicking a panel (`_panel_menu`, one persistent popup repopulated per click) and reset with `reset_panel_views`. Stored in `capture_state["panel_views"]` (so in every saved figure and the workbook state; `apply_state` treats a missing key as **none**, unlike the other keys, so an old figure never inherits the live overrides); `pptx_export.look_notes` lists customised panels. Reports need nothing else: all of them draw through `_render_figure_pages`.
- **`reportspec.py`** / **`reportgen_ui.py`** — what a report contains and in what order, chosen once for the PDF, the slides and the hand-over. `reportspec` (Tk-free) holds the **spec**, a plain dict `{"version", "sections": [{"id", "on"}, ...] (this order is the report's order), "skip": {section: [child ids]}, "options": {"sha": "short"|"none"}}`; children (each saved figure, each file's metadata) are on unless listed in `skip`, so a figure added later appears without redoing the choice. `SECTION_DEFS` = cover, **contents**, summary, figures, images, methods, calibration, metadata, files in the default **results-first** order (audit tables last); later milestones add sections there (glance, timing, results). `sanitise` puts a section an older spec lacks after the one before it in the default order (an old saved spec gets Contents right after its cover, on); `spec_from_sections` (the old names) never turns Contents on; the Quick look preset has none. The deck ignores `contents` until G5. `sanitise` makes any input a valid spec (unknown ids dropped, new sections appended, bad options reset); `active(spec, present)` → `[(id, skipped children)]` is what the builders read; `moved` / `with_on` / `with_child` / `with_option` / `with_all` return new specs; `spec_from_sections(names, "pdf"|"deck")` turns the old `sections=` names into a spec in the old order (so `report.SECTIONS` / `pptx_export.SECTIONS` callers are unchanged: PDF "cover" = cover + summary + methods + calibration + files, deck "title" = the first four); `BUILTIN_PRESETS` (Everything, Customer report, Quick look, Audit trail) and `clean_presets` / `all_presets` (a saved preset cannot take a built-in name); `inventory(...)` → `Inventory` says which sections have content, why not, and their children (`figure_id` = the figure's workbook id else `fig<N>`, `doc_key` = the file's workbook id else its name). `report.build_report(..., spec=)` and `pptx_export.build_deck(..., spec=)` build each section in the spec's order (in the PDF consecutive reportlab sections flow onto the same pages, figure and image pages are separate parts; a skipped figure leaves the rest renumbered; the calibration is not said twice when the methods state it; in the deck the calibration rides on the Summary slide, or gets its own when Summary is off). `Workspace.report_spec` (config `report_last`; a workbook's own `report.json`, an optional member older builds ignore, replaces it on open and is written on save; part of `_signature`), `report_presets` (config `report_presets`), `report_inventory()`, `set_report_spec()` (also updates the preview toolbar's ticks), `report_generator()`, `generate_report("pdf"|"pptx"|"both")` (asks for one path, the deck goes beside the PDF, says what was included, offers to open it) — **`Save PDF…`, `Export PowerPoint…`, the preview's ticks and the hand-over's report all use the same spec** (before, Save ignored the preview's ticks). `ReportGeneratorDialog` (Workbook ▸ Report generator…, ribbon Report ▸ Generator) keeps its behaviour in plain methods (`toggle_section`, `toggle_child`, `move`, `select_all`, `set_option`, `apply_preset`, `save_preset`, `delete_preset`) that the click handlers call, so the tests drive it without a mouse; every change is applied to the app at once. The cover-design picker (G3) and the redesigned pages (G4, G5) plug into it.
- **`pdfstyle.py`** / **`report.py`** — the look of the PDF (G4). `pdfstyle.Look` (`accent`, `font`, `bold`, `ink` = the accent darkened 20 % for text and table headers so amber still reads, `tint(t)`) comes from `pdfstyle.look(cover accent)`; the typeface is the bundled IBM Plex Sans registered with reportlab on first use (it has the "α" of "Al Kα", "µ" and "°" that built-in Helvetica lacks; falls back to Helvetica) and `styles(look)` holds the paragraph styles. `exporters._metadata_story(..., look=)` takes it (None = the old navy Helvetica, so the standalone metadata PDF is unchanged). `report.build_report` builds each part (a run of reportlab sections, images, figures) separately, and each flow part records **where its tagged headings landed** (`_mark` on a heading, `_Doc.afterFlowable` reads `self.page`, looking inside `KeepTogether` containers); figures record their first page from what `render_figure` returns. **Contents** is its own part built last: `_entries(parts)` → one line per section, and its files / figures when there are two or more, with page numbers from the parts' running start pages; the contents' own page count is settled by rebuilding (a long list runs over). The same entries become the **PDF bookmarks** (`set_toc`, also when Contents is off). The PyMuPDF footer (`_footer`) is the title, the section (`_page_sections`: the last tagged heading at or before the page) and "report page x of y", set in Plex from the file; a cover that leads the report has none. Cover: accent bar, 26 pt title, muted label column; tables are `hAlign="LEFT"` so they line up with the picture. Not done: section divider pages in the PDF (left to the slides), an appendix heading for the audit sections.
- **`covers.py`** — the cover picture of the report and the slides (Tk-free). A cover is `spec["cover"]` = `{"design", "image", "accent"}` (`reportspec.cover_of` / `with_cover`; sanitised there, the accent is `#RRGGBB` or "" = navy `#2C3E50`; the default design is `ribbon`, the old `sections=` names give `none`). Designs: five built in, drawn by matplotlib (`Figure` + `FigureCanvasAgg`, no pyplot) from the one accent colour and its tints — `ribbon`, `band`, `minimal`, `data` (the ticked survey, else the first ticked spectrum, else the first one loaded: `Workspace.cover_data()`; falls back to the ribbon without data), `grid` (peak map) — deterministic (fixed peaks and seed), 14–50 ms each; pictures in `assets/covers/` (`file:<name>`, `appinfo.cover_dir` / `cover_images`; `README.txt` there) and any browsed file (`image` + path), cropped from the middle to the space and never stretched (Pillow), stored as **JPEG** for the report and slides (a photograph was 1.3 MB as PNG, now ~140 KB) and PNG for the picker's thumbnails (Tk cannot show JPEG); `none`. The splash picture is deliberately not offered (its product name is cut by a 4:1 strip). `art(cover, "pdf"|"pptx", data)` → `Art(data, width, height, unit, note, fmt)`: 180 × 45 mm at the top of the PDF cover (inside the margins, above the letterhead), 13.333 × 1.55 in along the bottom of the title slide; `Art.data` is None (text-only cover) and `Art.note` says why when matplotlib / Pillow is missing or a picture is gone or unreadable. `build_report(..., cover_data=, notes=)` / `build_deck(..., cover_data=, notes=)` append the note, and `generate_report` shows it ("Note: the cover picture … was not found") instead of dropping the picture silently. Results are cached (key: design, file path + mtime + size, size, accent, JPEG, data hash). The dialog's **Cover** tab is a scrollable list of thumbnails with the design name (radio-style), "Use my own picture…", six accent swatches + "Other…", the details summary and "Edit details…"; `set_cover` / `set_accent` / `choose_picture` are the testable entry points, and **a preset never changes the cover** (`with_cover_of`): it says what goes in, the cover is the user's look. Tests that create a `Workspace` must restore `matplotlib.rcParams` in `tearDownClass` (a Workspace applies its theme globally, and `test_imagepages` reads the defaults; it only passed before because it ran before any app test).
- **`timing.py`** — how long an analysis took (Tk-free). `Region.extra` keys set by the readers: `n_scans`, `t_start` / `t_end` (ISO strings; a *run window*), `tz` ("UTC" or ""), `acq_mode` (`Scan` / `Snapshot` / `SnapMap`), `acq_code` (the raw Avantage `ACPROPID_MODE`), `analyser_mode` (words via `base.analyser_mode_name`: FAT and CAE → "Constant analyser energy (CAE)", FRR / CRR → "Constant retard ratio (CRR)"), `neutraliser`, `config`. `net_seconds(r)` = dwell × points × scans (dwell × scans for a snapshot / SnapMap, whose energy channels are recorded in parallel; dwell rounded to 6 significant digits because a `.vgd` holds float32), `None` when scans are unknown — never assumed 1. `summarise(docs)` works on the **distinct run windows** of all regions (a file with 12 points or 51 depth levels has one window; a session loaded as one `ThermoExperiment` doc has one per file): `active` = union of the windows (overlapping files counted once, idle gaps not at all), `span` = first start → last finish, `overhead` = active − counting time (moves, settling, sputtering, dead time), stated only when every region has both; `notes` say what is missing. Evidence for the Avantage fields: START/END are **UTC** (the files were written exactly one hour later on a UK machine in summer time; `tz` says so and `Run started` carries the label, `Date acquired` is unchanged); `DS_ACPROPID_DIRECTION` is 1 for every scan and 0 for every snapshot / SnapMap in the 107 reference files (`MODE` alone is 2 / 3 / 7 and is only kept as `acq_code`); `PERIODS` = number of scans (Casa's own `.vms` of the same scan has `n_scans` 10 = PERIODS 10); `ANPROPID_MODE` 1 is CAE (Casa writes FAT for it). A **SnapMap's `PERIODS` is 2 in the `.vgd` but 1 in Avantage's own `.avg` export**, so its scan count is left unknown (both readers stay identical on all 107 pairs). Thermo tilt / azimuth are not surfaced (unit unverified, always 0 in the data). `exporters.export_vamas` now writes the real `n_scans` (it wrote 1; Casa's export of the same data has 10). New `region_metadata` keys appear only when they have a value: `Acquisition software`, `Run started` / `Run finished`, `Anode voltage (kV)`, `Emission current (mA)`, `X-ray spot (µm)` (`W × L` when not square), `Sample tilt (°)`, `Take-off angle (°)` (VAMAS, non-zero only), `Analyser mode`, `Acquisition mode`, `Scans`, `Counting time`, `Source configuration`, and the `base.SESSION_KEYS` an `instrument` dict may carry (`Institution`, `Project`, `Experiment`, `Platter`, `Experiment ID`, `Sample description`, `Work function (eV)`, `Comments`). `readers/vamas.py` mines a CasaXPS export of Avantage data: `avantage_dump(lines)` reads the `;Dump of DataSpace` properties copied into the header comment (operator, instrument; first file only, so never times) and `casa_block_facts(lines)` the `X-ray spot-size:` / `LENS_MODE_NAME :` / `F/G Current:` block comments; the CasaXPS version gives `Acquisition software` "Thermo Avantage (VAMAS export by CasaXPS x)". **"ESCApe" names only the Kratos acquisition software (its `.experiment` files; the reader sets `Acquisition software` "Kratos ESCApe") or is the former app name;** `tests/test_appname.py` fails any other line containing it (it caught two old-app-name titles in `exporters.py`, now the neutral "Acquisition metadata"). **Kratos** (validated on `D:\Temp\2026-Q3 MI-LD-20264066-26-21`, an `.experiment` and HarwellXPS's VAMAS export of it, then on three more `.experiment` files): an `.experiment` stores the **dwell already summed over the sweeps** (`extra["dwell_total"]`; `dwell × points` is a whole number of seconds in all 372 regions, `dwell / sweeps` is constant per region type), so `net_seconds` is dwell × points and `Region.dwell_and_scans()` gives the per-sweep pair that VAMAS, `casafit` and `quant` want (`export_vamas` writes dwell / sweeps and the sweep count; Avantage, `.kal` and ordinary VAMAS dwells are per sweep). The sweep count is the int32 **88 bytes before the end of the `Uninitialized` tag** of each spectrum block (144 of 144 = the importer's `Sweeps`; the next best offset matched 72). Acquisition time is six consecutive int32 (year, month, day, hour, minute, second), one record before each *group* of regions acquired together; a region takes the last record before its block (`_start_for`, `t_start`, also `date_for_region`), 144 of 144 = the importer's `Acquired`. It is the **start** of the group; no reader of a Kratos file (`.experiment` or `.kal`, whose `Date Acquired` is likewise shared by several regions) records when a run ended, so `timing.summarise` reports first and last start and counting time, `end` / `active` / `overhead` stay `None` and a note says why. The time zone of Kratos times is unknown (`tz` empty). The Harwell VAMAS is recognised by the block comment `Vendor format : Kratos ESCApe .experiment` (it copies the summed dwell beside the sweep count; `dwell_total`, and its `Acquired :` line is `t_start`). `methods.generate(rows, calibration, timing_summary)` states spot, anode voltage / emission, analyser and acquisition mode, scans, and when / how long (`methods.timing_sentence`), only when recorded.
- **`metasummary.py`** — Tk-free tidying of `region_metadata` dicts: `summarise` splits fields into common-to-all vs varying (grouped by value → region labels, numbers ascending), `compact_labels`, `date_range`, `split_columns`. `layout_file` builds the lossless report layout (common block, per-sample line, scan rows with depth levels collapsed only when exact, per-level `strips`) shared by the PDF (`exporters._metadata_story`, portrait A4) and the slides (`pptx_export.py`); `column_weights` sizes its tables. Used by the Details panel for multi-selections (`Workspace._metadata_many`) and by the metadata PDF (`exporters._sample_block`); the metadata CSV stays flat.
- **`workbook.py`** — the `.xpscontainer` experiment workbook (Tk-free): a ZIP of JSON (`manifest`, `workbook` details, `state` = the current look, `figures`, `metadata` snapshot) plus the original data files verbatim under `data/<id>/`. Data are re-parsed through `readers.load_file` on open; ticked spectra are stored as `region_ref`s (file id + position + name/sample/etch level) and found again with `resolve_refs`, because `id(region)` is not stable. `save` writes a temp file then `os.replace`; `load` extracts only manifest-named members with sanitised names (no zip-slip) and refuses newer `format_version`s. **Sessions:** a `FileEntry` may carry `members` (files with their path below the session folder); `save` writes them under `data/<id>/<name>/…` (`safe_rel` on every part, `sha256_members` normalised so Windows and `/` paths hash alike), `load` rebuilds the folder tree with a `commonpath` check and `readers.load_file(entry.path)` reopens it; `format_version` is 2 only when a session is present, so ordinary workbooks stay readable by older copies. `Workspace.capture_state` / `apply_state` / `_temp_state` (in `spectradeck.py`) convert to and from the Tk variables — keep them in step with any new view setting (they mirror `_on_close`); `workbook_ui.py` holds the Details, Figures and AVG/VGD dialogs. **Stored results:** `Workbook.cache` (write only) is the HTML browser's payload without figures / cameras / maps (`Workspace._results_cache`, from `_display_for_export`, each `files[]` entry given its file id; switch: Workbook ▸ "Store the parsed results in the workbook", config `cache_in_workbook`, default on) that `save` writes as `cache/spectra.json.gz` (gzip, stored uncompressed in the ZIP) with `cache_version` and `source_files` (id, name, size, sha256) added by `encode_cache`, listed in the manifest under `cache` (member, cache_version, sha256 of the member, files) — **no `format_version` change** (older builds keep an unknown manifest key, find no member and ignore it). `save` now returns a list of notes (a cache over `CACHE_MAX_BYTES` = 64 MB is left out and says so). **The originals stay the only authority: opening still re-parses; the cache is advisory.** `read_cache(path)` → `(payload, "")` or `(None, reason)` and never raises: the manifest must name exactly `CACHE_MEMBER`, the member's sha256 must match, the version must be known, decompression is capped (`CACHE_MAX_JSON`), and the cache's `source_files` must equal the manifest's files (same ids and hashes). Its use so far: `htmlbrowser.write_html_from_workbook(book, html)` writes the data-browser page of a saved workbook without loading any instrument file (Workbook ▸ "Data browser from a saved workbook…"; the page says saved figures, holder photo, camera pictures and SnapMaps are not in it). Cost measured: 0.9 s and 1.4 MB for a 2 754-spectrum Avantage experiment, 0.6 s and 0.14 MB for the MXene fits. **`report.py`** builds the customer report (reportlab cover + metadata, matplotlib figure pages via `Workspace._report_figure_pages`, merged and footed with PyMuPDF). **`pptx_export.py`** builds the 16:9 deck (title, summary, data files, metadata tables, one slide per figure page with caption + speaker notes) with python-pptx; figure pictures come from `Workspace._render_figure_pages`, the same renderer the PDF report uses (it applies each figure's saved look through `_temp_state` and hands pages to a `consume` callback while the print style is active). **`annotations.py`** holds user edits *beside* the data (display names, notes, metadata edits, BE shifts, peak markers, calibration log) keyed by workbook file id + sample / region name / position, stored in the workbook (`annotations.json`) and never applied to the readers' output: `SpectrumFile.annotations`/`file_id` let `region_metadata` / `samples_metadata` apply them, and `Workspace._display(region)` returns a shifted/renamed copy (the photon energy moves with a BE shift, so kinetic energies are unchanged) that drawing (`_draw_page`), exports (`_write_export`) and reports use — call `_ann_changed()` after any change. `calibration.py` (peak finding, statement), `xpslines.py` + `assets/xps_lines.json` (element lines, candidate lookup, auto-label). - **`quant.py`** — quantification from CasaXPS fits (Tk-free, numpy only to evaluate). `fit_rows(display_region, curves=False)` gives one JSON-ready row per distinct fit region (`casafit.distinct_regions`; `Curves.fit_region` carries the `FitRegion`): RSF, region **area = ∫(data − background) in counts/s·eV** (dwell × scans divided out, the scale of the stored component areas — checked: ∫ of each reconstructed component = its stored area; where the background is not reproduced it falls back to Σ components, `basis`), `area_t` with the transmission function divided out (only when the file has one; **off by default** in `normalise(..., transmission=)` because it is unknown whether CasaXPS applies it to Kratos data), region limits and component positions in the *drawn* BE frame (`hν_display − (pos_ke + shift_of_comps)`), and per component the chemical-state key/name (`state_of`: INDEX ≥ 0 shares a state, a group tag equal to the region's name is not a name — the rule `plots.draw_fit` uses). `normalise(rows, include)` → at % = area/RSF over the included rows (rows with no RSF/area say why), `states(row, at)` splits an element, `csv_rows(groups, include, transmission)` is the quantification table (one group per sample and depth level, each normalised on its own; the page writes the identical table — `viewer.js` `quantGroups` / `quantNormalise` / `quantStates` / `quantTable` / `quantCsv`, compared with it in `viewer_test.js`). Checked on the vanadium example (96 and 25 scans, two overlapping C 1s regions). - **`vamasmeta.py`** — metadata carried in VAMAS comments (Tk-free): `encode(md)` / `decode(lines)` write and read a `=== <app name> metadata ===` … `=== end of … ===` block of `key: value` lines (characters beyond Latin-1 are escaped as a backslash-u sequence, a literal backslash before "u" is doubled; the former app name's marker is still read). `EXPERIMENT_KEYS` go in the header comment, everything else in each block comment. `apply_to_region` restores name / anode / power / technique / date / position / etch level and time / lens / aperture / quality and keeps the rest in `Region.extra["preserved_metadata"]`, which `SpectrumFile.region_metadata` merges (never over a non-empty computed value). `VAMAS_OWN` (photon energy, pass energy, dwell, step, points, BE range) is never taken from the text. `exporters.export_vamas(..., metadata=[one dict per region], experiment_metadata=)` writes it (the file is now Latin-1; photon energy, abscissa start and step to 10 significant digits); `Workspace._write_export` and `handover.spectra_parts` pass `parser.region_metadata`. `readers/vamas.py` restores it and rebuilds the sputter prefill (`_restore_sputter`). - **`lineshapes.py`** / **`casafit.py`** — CasaXPS fits from VAMAS (numpy needed only to evaluate). `casafit.parse(comment_lines)` → `Fit` (`FitRegion`s with the six numbers after the averaging width as `params`, `FitComponent`s with INDEX group, `calib_shift` = Σ(A − M) of `Calib` lines, `lines`, and `block` = the whole CasaXPS section of the comment **verbatim**, which is what `to_lines` writes back so CasaXPS reopens its own fit). `casafit.calibration(comment_lines)` → `Calib` (`shift`, `measured`, `assigned`, `region_shift`, `comp_shift`) is independent of the fit, so a block with a `Calib` line and no fit keeps its correction. `readers/vamas.py` sets `Region.fit` per block (a depth profile has one per block) plus `extra["comment_lines"]` and `extra["n_scans"]`. **Frames** (validated on real files, see `tests/test_casafit.py` and `tests/test_casacalib.py`): region limits and component positions are KE; a `Calib` line **without** the `Regions` / `Comps` flags means they are in the *calibrated* frame (raw KE = position + shift, raw BE = hν − position − shift), **with** the flags CasaXPS moved them with the spectrum and they are raw KE (`Fit.shift_of_regions/_of_comps` return the shift to add; each flagged line drops out of its own sum). `curves` works on raw KE only. Intensity is counts/s, so curves are multiplied by dwell × scans to match `Region.counts`. Because everything is anchored in KE, `_display` (which moves hν with a BE shift) needs no fit handling. `casafit.curves` returns `Curves` aligned with the spectrum's points (NaN outside the region, `residual_rms`, `approximate`, `scale_known`, `background_known`); overlapping regions with one name collapse to the widest (`distinct_regions`); an unreproduced background gives components but no envelope. `lineshapes`: `GL`/`SGL` exact; `LA`/`LF` are reconstructions (`GAUSS_K` from earlier calibration on Harwell data; a sweep on the six real fits found no better value beyond noise — do not retune on so few); Shirley (iterative, `avg`-point end levels), linear and **`U 2 Tougaard`** (`tougaard_u2`: `K(T) = B T / (C + T²)²` summed over the data above each point, anchored at the mean of the last `avg` points; B = `params[2]`, C = |`params[3]`| because CasaXPS stores C negative — residual 2–5 % of the range on 16 real MXene regions); other Tougaard types return None. `plots.draw_fit` overlays it on single-spectrum panels (`draw_stack(..., fit=)`; the legend names a group by its tag unless that is just the region's name, and lists over six entries go below the axes); `Workspace._fit_overlay` + `fit_vars` (Components / Envelope / Background toggles, in config and in `capture_state` as `fit_show`). `exporters.export_vamas` writes `to_lines(r.fit)` first in the block comment and the real scan count; `export_csv` adds `fit_columns`; `region_metadata` gets a "CasaXPS fit" line. The fit is read-only: never edited or refitted.

Ticks are a set of `id(region)` (`Workspace.checked`) so they survive tree rebuilds (filter, theme change, adding/removing files). Tick boxes are `PhotoImage`s on the Treeview rows; a click counts only when `identify_element` reports `"image"`. Redraws go through `_schedule_render` (`after_idle`).
  - **Grouping/stacking:** `group_regions` (by name, ≥50 % x-range overlap, or name per sample / per file) → one panel per group; the pure drawing functions live in `plots.py` (`draw_stack`, `draw_heatmap`, `draw_waterfall3d`, `add_ke_axis`, `norm_factor`, `trace_label`; re-exported by `spectradeck`, so `ee.draw_stack` etc. still work); `draw_stack` draws one spectrum plain or several stacked with an offset and optional normalisation. `view_var` switches each panel to `draw_heatmap` (pcolormesh + colour bar, `heat` ramp per palette) or `draw_waterfall3d` (mplot3d); non-Stack views z-sort each group in `_groups`. `scale_var` / `ke_var` choose the x axis (`add_ke_axis` adds the mirrored top axis); "At cursor" cursors are always stored as binding energy.
  - **View window:** `panels_var` (panels per page) + `panel_start` (row-aligned), `traces_var` + `trace_start` (window over long stacks); wheel / Shift+wheel / scrollbar / slider all just move those two and re-render. Only the visible panels and traces are drawn.
  - **Multiple files:** `Workspace.docs` is a list of readers; `region_parser` maps `id(region)` → its reader (needed for metadata, positions, images, export). `Region.source` labels traces when more than one file is loaded.
  - **Colour = file/sample, tree = legend:** `colour_slots` (one slot per file when several are loaded, else per sample) and `stack_colours` (categorical, or a ramp when a stack shares one slot) are pure functions; `_assign_colours` stores each ticked region's colour in `trace_color`, and `_refresh_boxes` draws that colour as the tree swatch, so tree and plot always agree. `draw_stack` puts end-of-trace labels in a right gutter (`dodge` keeps them apart; the gutter is reserved in `_draw_page`, not by `tight_layout`) and replaces y-ticks on stacks with a scale bar.
  - **Chrome:** one view row (group, normalise, offset), a contextual footer (panels/traces selectors; the scrollbar and trace slider are only packed when they can act, via `_layout_bottom`), a status bar for counts, `Tooltip` for hints, and an info column whose Images / Stage-map notebook only exists when the loaded files have images or positions (`_refresh_info`). The matplotlib toolbar keeps Back/Forward enabled because Windows paints disabled image buttons in the system grey.
  - **Theme:** `set_theme` re-applies ttk styles, rebuilds tick-box images and the tree, recreates the matplotlib toolbar (its icons are recoloured), and updates `matplotlib.rcParams`; PDFs are always drawn inside `rc_context(mpl_rc(PRINT))`.
  - Settings persist in `~/.spectradeck_config.json` (`load_config`/`save_config`); camera calibration in `~/.spectradeck_calib.json` (the files of the former name `~/.escape_explorer_*.json` are read until the first save).

## Verifying a reader

Readers are validated against **the same data in another format**, never by eye: a text export next to a binary file (`.vgd` ↔ `.avg`), or a vendor's own VAMAS export (`.spe`, `.kal`, `.avg` ↔ `.vms`). Compare energy arrays, counts (allowing documented factors such as dwell time or transmission), hν, pass energy, dwell and positions. Beware that a partner export can itself be wrong (a Casa VAMAS of the Scienta `.txt` has a reversed axis) — check physics (peak positions) before "fixing" a reader to match it. To exercise the GUI without instrument files, monkeypatch `EscapeParser.load` (or a reader's `load`) to fill `regions` and call `_build_tree()` on synthetic `Region`s.
