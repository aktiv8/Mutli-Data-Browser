# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

eXPoSe SpectraDeck: a single-window Tkinter app that browses, plots and exports XPS spectra from many instruments — Kratos ESCApe (`.experiment`) and Vision (`.kal`), VAMAS (any vendor), Thermo Avantage (`.avg`/`.vgd`/`.avx`, or a whole experiment folder / `.VGX`), PHI MultiPak (`.spe`), Scienta SES (`.txt`) — to CSV or VAMAS, and turns an experiment into a customer report (PDF, slides, hand-over ZIP, offline HTML browser). See `README.md` for the user-facing tour.

## Commands

```bash
python launch.py                # create ./.venv, install deps, start the app (python3 on macOS/Linux)
python launch.py --setup-only   # build the venv without starting the app
python launch.py --reinstall    # rebuild the venv from scratch
python launch.py --check        # report venv / tkinter / app-file status
python spectradeck.py       # run directly with the current interpreter
python -m unittest discover tests            # unit tests (synthetic files, no instrument data needed; includes palette contrast/separation and colour-rule tests)
XPS_CORPUS=<folder> python -m unittest tests.test_corpus   # every recognised file in a folder must load
```

There is no linter or build step. Dependencies (`matplotlib`, `pillow`, `reportlab`, `pymupdf`, `python-pptx`) are in `requirements.txt`; `launch.py` keeps a `REQUIRED` fallback list that must stay in sync and re-installs when the requirements file's SHA-1 changes. `tkinter` comes from the base Python, not the venv. Run the tests with the venv's interpreter (`.venv/Scripts/python` on Windows, `.venv/bin/python` elsewhere): the report tests need reportlab, PyMuPDF, matplotlib and python-pptx.

## Conventions (rules that cut across modules)

- **The app name** lives in `appinfo.NAME` ("eXPoSe SpectraDeck", formerly "ESCApe Explorer") — use the constant, never a literal. "ESCApe" names only the Kratos acquisition software (its `.experiment` files; the reader sets `Acquisition software` "Kratos ESCApe") or is the former app name; `tests/test_appname.py` fails any other line containing it.
- **User edits live in `annotations.py` beside the data and are applied on the way out — never mutate what a reader returns.** `Workspace._display(region)` is the copy that drawing, exports and reports use; call `_ann_changed()` after any change to `self.ann`.
- **Optional libraries are optional.** The app must still start without matplotlib / Pillow / PyMuPDF / python-pptx (`HAVE_MPL`, `HAVE_PIL`, `pdf_preview.HAVE_PDF`); a feature that needs one says so instead of failing. Modules marked *Tk-free* import no Tk so tests and the report builders run headless; numpy / matplotlib / Pillow are imported inside the functions that draw.
- **Readers:** always use `read_bytes` (never leave file handles open); a reader only fills `regions` and calls `_finish()`.
- **State that is saved** (`Workspace.capture_state` / `apply_state` / `_temp_state`) mirrors the Tk variables and `_on_close`: keep them in step with any new view setting. A saved figure applies its own state when drawn, so a key missing from an old state must not inherit the live one (`panel_views` treats a missing key as *none*).
- **One report choice.** What a report contains is one `reportspec` spec used by `Save PDF…`, `Export PowerPoint…`, the PDF preview's ticks and the hand-over package.
- **One Tk root.** `splash.begin` makes the only root before the heavy imports; `PhotoImage`s created without a master (`SwatchCache` …) rely on it.
- **Ribbon buttons are shortcuts:** every target must still be in `_build_menu` (`tests/test_ribbon.py` checks); nothing may live only on a button.
- **Tests that create a `Workspace`** must restore `matplotlib.rcParams` in `tearDownClass` (a Workspace applies its theme globally; `test_imagepages` reads the defaults).
- **Writing files on Windows:** the metadata CSV is UTF-8 with a BOM (the "α" of "Al Kα" cannot be written with the cp1252 default; this once made the hand-over ZIP silently drop the CSV); VAMAS is Latin-1 with anything beyond escaped.

## Architecture

`spectradeck.py` is the entry point (window, dialogs, `main()`, the `Workspace`); everything else is a module beside it.

### Readers and instrument data

- **`readers/`** — one reader per format behind `readers.load_file(path)`. `readers/__init__.py` holds the `READERS` registry and picks a reader by **content sniffing** first (extension is only a hint), so renamed files still open; add a format by writing a `SpectrumFile` subclass with a `sniff(head, ext)` function and registering it there (this also feeds the Open dialog filters).
  - `readers/base.py`: `Region` / `TreeNode` / `ImageBlob` dataclasses and the `SpectrumFile` base class. A reader fills `regions` (+ `instrument`, optional `depth_profile`, `_sample_pos`, `images`) and calls `_finish()`; the tree, per-region metadata and positions then come from the base class. Helpers: `canon_region_name` ("C1s" → "C 1s", surveys → "Survey", so the same core level groups across formats), `guess_region_name` (a "core level" on a >250 eV axis is a survey), `kv_from_lines`, `analyser_mode_name`.
  - `Region.energy` is **binding energy** for XPS whenever the photon energy is known (BE = hν − KE, as CasaXPS does); otherwise the native axis is kept and `energy_label` says so (only "Binding…" axes are inverted when plotted).
  - `vamas.py`: field-by-field ISO 14976 parser. Header layout varies by experiment mode (e.g. `SDPSV` has no "number of spectral regions"), so `load()` tries the expected layout then alternatives; numbers between the source label and analyser mode are read by type because the count varies by mode; `IRREGULAR` scans have no start/step (the first corresponding variable is the abscissa). It also reads the CasaXPS fit and charge correction of each block (below) and mines a CasaXPS export of Avantage data: `avantage_dump(lines)` reads the `;Dump of DataSpace` properties copied into the header comment (operator, instrument; first file only, so never times) and `casa_block_facts(lines)` the `X-ray spot-size:` / `LENS_MODE_NAME :` / `F/G Current:` block comments; the CasaXPS version gives `Acquisition software` "Thermo Avantage (VAMAS export by CasaXPS x)". A HarwellXPS export of a Kratos file is recognised by the block comment `Vendor format : Kratos ESCApe .experiment` (it copies the summed dwell beside the sweep count → `dwell_total`, and its `Acquired :` line is `t_start`).
  - `phi_spe.py` (16-byte preamble, all 96-byte block headers, then float64 blocks; counts/s), `scienta_txt.py`, `kratos_kal.py`, `kratos_experiment.py` (the original reverse-engineered `EscapeParser`).
  - **Kratos `.experiment` facts** (validated on an `.experiment` and HarwellXPS's VAMAS export of it, then three more files): the file stores the **dwell already summed over the sweeps** (`extra["dwell_total"]`; `dwell × points` is a whole number of seconds in all 372 regions, `dwell / sweeps` is constant per region type), so `net_seconds` is dwell × points and `Region.dwell_and_scans()` gives the per-sweep pair that VAMAS, `casafit` and `quant` want (Avantage, `.kal` and ordinary VAMAS dwells are per sweep). The sweep count is the int32 **88 bytes before the end of the `Uninitialized` tag** of each spectrum block (144 of 144 = the importer's `Sweeps`; the next best offset matched 72). Acquisition time is six consecutive int32 (year … second), one record before each *group* of regions acquired together; a region takes the last record before its block (`_start_for`, `t_start`, `date_for_region`), 144 of 144 = the importer's `Acquired`. It is the **start** of the group: no reader of a Kratos file (`.experiment`, or `.kal` whose `Date Acquired` is likewise shared) records when a run ended, and the time zone is unknown (`tz` empty).
  - **Thermo Avantage.** `thermo_avg.py` defines `DataSpace` and `ThermoDataSpaceFile._from_dataspace`, shared with `thermo_vgd.py` (pure-Python OLE2 in `ole2.py`, no `olefile`). `.vgd` property ids → `DS_*` names are the `PID_NAMES` table; the axis stream is decoded by anchoring on the expected item counts, and the **axis type code** is the int32 right after each axis's linear flag (1 ENERGY, 3 X, 4 Y, 6 ETCHLEVEL, 8 ETCHTIME, 10 POSITION: `AXIS_CODES`). `dataspace_kind(ds)` classifies a DataSpace as `spectrum` / `position` (one spectrum per analysis point) / `levels` (depth profile; etch time from the ETCHTIME axis) / `map` (SnapMap) / `image` (camera picture: value type 13, one packed **B<<16|G<<8|R** float per pixel, checked pixel for pixel against Avantage's PNG export; the `.vgd` reader leaves `VGData` unread and the PNG is made by `ImageBlob.loader` on demand) / `table` (auto-height Z values: `value_table`, no regions; the `.avg` dump does not list per-point X/Y there) / `other`. **Both readers must stay identical on every pair** (validated on 146 `.vgd`/`.avg` pairs, 107 for the timing fields). A DataSpace with no axes raises "this DataSpace is empty" (an aborted acquisition). A SnapMap `.vgd` is handed over as raw doubles (`DataSpace.raw`, ~0.1 s) rather than per-pixel lists.
  - `thermo_vgx.py` parses an Avantage `.VGX` (OLE2 of MFC objects; only the `FF FE FF`-prefixed UTF-16 strings are read): experiment / project / platter / date folder from the root, then group (source configuration, e.g. "X-Ray005 200um - FG  ON") → sample → step nodes ordered by their `Embedding N` numbers (= run order). A sample node's own strings list its scans differently per scan type, so they are only matched against folder names. `thermo_experiment.ThermoExperiment` opens a **folder or a `.VGX`** as one `SpectrumFile` (`readers.load_file(path, progress=)`; `looks_like_experiment`, `find_vgx` looks up to 4 levels above a folder): sample = the folder below the configuration, `Region.sample` = "<sample> <Pt #001a>" for multi-point scans, `.vgd` preferred over `.avg`, `errors` / `skipped` collected without stopping, `members` = every file used (for the workbook), custom `_build_tree` (experiment → `samplegroup` → `sample` → scans; depth-profile samples use `regionfolder` levels; duplicate core levels get the scan name). Camera images become `ImageBlob`s (`fmt="png"`, `calib`, `sample`, label time from the file name because stored times are UTC).
  - **Avantage timing evidence** (`Region.extra`, see `timing.py`): START/END are **UTC** (the files were written exactly one hour later on a UK machine in summer time; `tz` says so and `Run started` carries the label, `Date acquired` is unchanged); `DS_ACPROPID_DIRECTION` is 1 for every scan and 0 for every snapshot / SnapMap in the 107 reference files (`MODE` alone is 2 / 3 / 7 and is only kept as `acq_code`); `PERIODS` = number of scans (Casa's own `.vms` of the same scan has `n_scans` 10 = PERIODS 10); `ANPROPID_MODE` 1 is CAE (Casa writes FAT for it). A **SnapMap's `PERIODS` is 2 in the `.vgd` but 1 in Avantage's own `.avg` export**, so its scan count is left unknown. Thermo tilt / azimuth are not surfaced (unit unverified, always 0 in the data).
- **`timing.py`** — how long an analysis took (Tk-free). `Region.extra` keys set by the readers: `n_scans`, `t_start` / `t_end` (ISO strings; a *run window*), `tz` ("UTC" or ""), `acq_mode` (`Scan` / `Snapshot` / `SnapMap`), `acq_code` (the raw Avantage `ACPROPID_MODE`), `analyser_mode` (words: FAT and CAE → "Constant analyser energy (CAE)", FRR / CRR → "Constant retard ratio (CRR)"), `neutraliser`, `config`. `net_seconds(r)` = dwell × points × scans (dwell × scans for a snapshot / SnapMap, whose energy channels are recorded in parallel; dwell rounded to 6 significant digits because a `.vgd` holds float32), `None` when scans are unknown — never assumed 1. `summarise(docs)` works on the **distinct run windows** of all regions (a file with 12 points or 51 depth levels has one window; a session loaded as one `ThermoExperiment` doc has one per file): `active` = union of the windows (overlapping files counted once, idle gaps not at all), `span` = first start → last finish, `overhead` = active − counting time (moves, settling, sputtering, dead time), stated only when every region has both; `notes` say what is missing (for Kratos: first and last start and counting time only; `end` / `active` / `overhead` stay `None`).
- **Acquisition metadata fields** (`SpectrumFile.region_metadata`): keys appear only when they have a value — `Acquisition software`, `Run started` / `Run finished`, `Anode voltage (kV)`, `Emission current (mA)`, `X-ray spot (µm)` (`W × L` when not square), `Sample tilt (°)`, `Take-off angle (°)` (VAMAS, non-zero only), `Analyser mode`, `Acquisition mode`, `Scans`, `Counting time`, `Source configuration`, and the `base.SESSION_KEYS` an `instrument` dict may carry (`Institution`, `Project`, `Experiment`, `Platter`, `Experiment ID`, `Sample description`, `Work function (eV)`, `Comments`). `exporters.export_vamas` writes the real `n_scans` and, for Kratos, dwell / sweeps and the sweep count.
- **`snapmap.py`** / **`snapmap_ui.py`** — `MapCube` (float32 `array` `[iy][ix][channel]`, `x0/dx/y0/dy` in µm in the *image* frame, `stage_x_mm/stage_y_mm`), attached as `Region.extra["cube"]` beside the summed-spectrum region; numpy only inside `image` / `roi_spectrum` / `rect_mask` / `default_window` / `colour_range`. `default_window` takes a sloping baseline off, ignores the outer tenth, favours the middle and enforces ≥ 2 eV (weak Cu 2p peaks fooled simpler rules). `SnapMapDialog` (energy window by `SpanSelector`, ROI by `RectangleSelector`, element switch, overlay on the nearest camera image, PNG/CSV export) opens from Tools, the tree context menu or a double-click (`Workspace.open_snapmap`).
- **`snapshot.py`** — camera-image geometry from `ImageBlob.calib`: `stage_to_pixel` / `pixel_to_stage` / `markers` / `map_rectangle` / `nearest_image` / `view_of(calib, positions, sites)` (the points and map outlines inside a picture; used by the HTML browser and the report pages). **Measured** on K-Alpha+ (registering neighbouring photos, r 0.53–0.80 vs < 0.3 for the other sign choices): image x runs *against* stage X, image y *with* stage Y (`X_DIR`, `Y_DIR`); a SnapMap's own axes follow the image (they overlay the photo without a flip) and are centred on its stage position. `Workspace._render_snapshot` draws it (used instead of the holder-photo overlay for calibrated images); thumbnails are filled one per `after` tick (`_fill_thumbs`).
- **`lineshapes.py`** / **`casafit.py`** — CasaXPS fits from VAMAS (numpy needed only to evaluate). `casafit.parse(comment_lines)` → `Fit` (`FitRegion`s with the six numbers after the averaging width as `params`, `FitComponent`s with INDEX group, `calib_shift` = Σ(A − M) of `Calib` lines, `lines`, and `block` = the whole CasaXPS section of the comment **verbatim**, which is what `to_lines` writes back so CasaXPS reopens its own fit). `casafit.calibration(comment_lines)` → `Calib` (`shift`, `measured`, `assigned`, `region_shift`, `comp_shift`) is independent of the fit, so a block with a `Calib` line and no fit keeps its correction. `readers/vamas.py` sets `Region.fit` per block (a depth profile has one per block) plus `extra["comment_lines"]` and `extra["n_scans"]`. **Frames** (validated on real files, see `tests/test_casafit.py` and `tests/test_casacalib.py`): region limits and component positions are KE; a `Calib` line **without** the `Regions` / `Comps` flags means they are in the *calibrated* frame (raw KE = position + shift, raw BE = hν − position − shift), **with** the flags CasaXPS moved them with the spectrum and they are raw KE (`Fit.shift_of_regions/_of_comps` return the shift to add; each flagged line drops out of its own sum). `curves` works on raw KE only; intensity is counts/s, so curves are multiplied by dwell × scans to match `Region.counts`. Because everything is anchored in KE, `_display` (which moves hν with a BE shift) needs no fit handling. `casafit.curves` returns `Curves` aligned with the spectrum's points (NaN outside the region, `residual_rms`, `approximate`, `scale_known`, `background_known`); overlapping regions with one name collapse to the widest (`distinct_regions`); an unreproduced background gives components but no envelope. `lineshapes`: `GL`/`SGL` exact; `LA`/`LF` are reconstructions (`GAUSS_K` from earlier calibration on Harwell data; a sweep on the six real fits found no better value beyond noise — do not retune on so few); Shirley (iterative, `avg`-point end levels), linear and **`U 2 Tougaard`** (`tougaard_u2`: `K(T) = B T / (C + T²)²` summed over the data above each point, anchored at the mean of the last `avg` points; B = `params[2]`, C = |`params[3]`| because CasaXPS stores C negative — residual 2–5 % of the range on 16 real MXene regions); other Tougaard types return None. `plots.draw_fit` overlays it on single-spectrum panels (`draw_stack(..., fit=)`; the legend names a group by its tag unless that is just the region's name, and lists over six entries go below the axes); `Workspace._fit_overlay` + `fit_vars` (Components / Envelope / Background toggles, in config and in `capture_state` as `fit_show`). `exporters.export_vamas` writes `to_lines(r.fit)` first in the block comment; `export_csv` adds `fit_columns`; `region_metadata` gets a "CasaXPS fit" line. The fit is read-only: never edited or refitted.
- **CasaXPS charge correction on the region** — `Region.calibration_shift` (eV, binding axes only) is what the file itself says to add; `extra["casa_calib"]` holds `measured` / `assigned` / `shift` / `inherited`. `readers/vamas.py` (`_own_calibration`, `_share_calibration`) sets it from each block's `Calib` line, then a block **without** one takes the correction of the other blocks of its `Region.sample` when they all agree (a wide scan next to calibrated core levels; per-level corrections that differ are not shared). `Region.energy` stays the file's raw axis: `Workspace._display` adds `Annotations.shift_for(fid, sample, name, r.calibration_shift)` — the user's own shift wins by scope, otherwise the file's — and marks the copy with `shift_applied`. Every reader of the shift (`_display`, `_marker_shift`, `_binding_at`, `htmlbrowser`, `apply_metadata`) passes the default; `shift_for(..., None)` tells "user set none" from zero. **Export round trip:** the copy carries hν + shift, so `export_vamas` writes hν − `calibration_shift` and a `Calib` line (`casafit.calib_line`, with the `Regions Comps` flags so a fit stays in the raw frame) when the block has none, so re-reading applies the correction once. `calibration.casa_statement` / `Workspace._casa_calibrations` add the sentence to the methods text; the metadata row is "BE calibration (CasaXPS)".
- **`vamasmeta.py`** — metadata carried in VAMAS comments (Tk-free): `encode(md)` / `decode(lines)` write and read a `=== <app name> metadata ===` … `=== end of … ===` block of `key: value` lines (characters beyond Latin-1 are escaped as a backslash-u sequence, a literal backslash before "u" is doubled; the former app name's marker is still read). `EXPERIMENT_KEYS` go in the header comment, everything else in each block comment. `apply_to_region` restores name / anode / power / technique / date / position / etch level and time / lens / aperture / quality and keeps the rest in `Region.extra["preserved_metadata"]`, which `SpectrumFile.region_metadata` merges (never over a non-empty computed value). `VAMAS_OWN` (photon energy, pass energy, dwell, step, points, BE range) is never taken from the text. `exporters.export_vamas(..., metadata=[one dict per region], experiment_metadata=)` writes it (photon energy, abscissa start and step to 10 significant digits); `Workspace._write_export` and `handover.spectra_parts` pass `parser.region_metadata`. `readers/vamas.py` restores it and rebuilds the sputter prefill (`_restore_sputter`). Validated by exporting and re-reading real Kratos `.kal` / `.experiment` and Avantage `.avg` files: every metadata key comes back except values the source never had.
- **`sputter.py`** / **`sputter_ui.py`** — per-sample ion gun settings (ion, charge, energy, current + unit, raster, etch rate + unit; `sanitise` fills a full dict, unknown stays `None`), `fluence = I·t/(q·e·A)`, `depth_nm`, `missing(mode, s)` (what to enter), `from_text` ("5 keV Ar+") / `from_properties` (Avantage `...IONGUN...` keys: text and eV-keyed energy only — a unit is never guessed) / `merge_prefill`. Stored in `Annotations.sputter` (sample key → settings) and applied in `apply_metadata` (per depth level: ion, energy, current, raster, rate, `Depth (nm)`, `Fluence`), so `methods._beam_sentence` and the HTML browser see them. `viewdata.Z_MODES` has `Depth` and `Fluence` (`resolve_z/z_sorted(..., sputter_for)`; judged on their own values, not on etch-time distinctness) and `z_unavailable` writes the "enter X" notes shown by `_draw_page`. Readers set `SpectrumFile.sputter_hint` (Kratos: the `N keV Ion+` string in the etch settings; PHI: kv keys; Avantage: the `DepthProfileIonGun*` properties) and `sputter_prefill()` merges it with the `Ion gun / sputtering` text. `Workspace.sputter_samples/get/set/prefill` serve the dialog.
- **`elements.py`** / **`reels.py`** / **`iss_ui.py`** — ISS and REELS. `elements`: `ELEMENTS` (Z, most-abundant-isotope mass, name; the table of the author's XPSView project), `ION_MASS`, `kinematic_factor` (E1/E0 = [(cos θ + √(A² − sin²θ))/(1 + A)]²; None when a lighter target cannot scatter that far — for θ ≥ 90° that means A < 1), `iss_energy`, `iss_table`, `candidates` (window ±(0.5 % E0 + 2 eV), nearest first), `mass_from_energy` (bisection), `parse_symbols`, `marks_for`; tests check the 180° and 90° closed forms. `reels`: `elastic_peak`, `loss_axis`, `baseline` (median between the elastic tail and the lower pick, else the minimum), `band_gap(loss, y, p1, p2)` (tangent through two picks ∩ baseline, None unless the edge rises and the gap is positive), `tangent_points`. Stored in `Annotations`: peak markers may carry `kin: True` (a kinetic energy: not moved by the BE shift, drawn as hν − KE on a binding axis; `plots.draw_stack(markers=)` takes `(value, text[, kin])`, the HTML payload and `viewer.js` honour the flag) and `Annotations.reels` (region key → `{elastic, p1, p2, gap, base, slope}`, applied to the metadata as `REELS band gap (eV)`). `plots.draw_reels` overlays the construction on single-spectrum panels (`draw_stack(..., reels=)`, scaled by the panel's normalisation). `iss_ui.IssReelsDialog` uses `Workspace._click_cb` like Identify, and the helpers `spectrum_regions`, `kinetic_from_event`, `data_from_event`, `click_panel_spectra`, `reels_get/reels_set`; it refuses clicks on panels that show several spectra.
- **`quant.py`** — quantification from CasaXPS fits (Tk-free, numpy only to evaluate). What is recorded is what is used: nothing is guessed, a region with no RSF or area is left out and says why. `fit_rows(display_region, curves=False)` gives one JSON-ready row per distinct fit region (`casafit.distinct_regions`; `Curves.fit_region` carries the `FitRegion`): RSF, region **area = ∫(data − background) in counts/s·eV** (dwell × scans divided out, the scale of the stored component areas — checked: ∫ of each reconstructed component = its stored area; where the background is not reproduced it falls back to Σ components, `basis`), `area_t` with the transmission function divided out (only when the file has one; **off by default** in `normalise(..., transmission=)` because it is unknown whether CasaXPS applies it to Kratos data), region limits and component positions in the *drawn* BE frame (`hν_display − (pos_ke + shift_of_comps)`), and per component the chemical-state key/name (`state_of`: INDEX ≥ 0 shares a state, a group tag equal to the region's name is not a name — the rule `plots.draw_fit` uses). `normalise(rows, include)` → at % = area/RSF over the included rows, `states(row, at)` splits an element, `csv_rows(groups, include, transmission)` is the quantification table (one group per sample and depth level, each normalised on its own), `profile(groups, mode, include, transmission)` a depth profile (modes `element` / `state` / `share`; a region twice at one level is shown once but still counts in the total until unticked). Checked on the vanadium example (96 and 25 scans, two overlapping C 1s regions). The other program's (XPSView / HarwellXPS) quantification divides by dwell only, counts overlapping regions twice and merges all INDEX −1 components, so its numbers are not a reference.

### Annotations, workbook and exports

- **`annotations.py`** holds user edits *beside* the data (display names, notes, metadata edits, BE shifts, peak markers, sputter settings, REELS results, calibration log) keyed by workbook file id + sample / region name / position, stored in the workbook (`annotations.json`) and never applied to the readers' output: `SpectrumFile.annotations` / `file_id` let `region_metadata` / `samples_metadata` apply them, and `Workspace._display(region)` returns a shifted / renamed copy (the photon energy moves with a BE shift, so kinetic energies are unchanged). `calibration.py` (peak finding, statement), `xpslines.py` + `assets/xps_lines.json` (element lines, candidate lookup, auto-label). Plot clicks are routed through `_click_cb` (Identify) / `_pick_cb` (one-shot, Calibrate) before the 'At cursor' handler. **`importplan.py`**: `find_pairs` / `apply_choice` for `.avg` + `.vgd` copies of one dataset (`Workspace._resolve_duplicate_formats`, config key `dup_format`).
- **`workbook.py`** — the `.xpscontainer` experiment workbook (Tk-free): a ZIP of JSON (`manifest`, `workbook` details, `state` = the current look, `figures`, `metadata` snapshot, `holder.json`, `annotations.json`, an optional `report.json`) plus the original data files verbatim under `data/<id>/`. Data are re-parsed through `readers.load_file` on open; ticked spectra are stored as `region_ref`s (file id + position + name/sample/etch level) and found again with `resolve_refs`, because `id(region)` is not stable. `save` writes a temp file then `os.replace` and returns a list of notes; `load` extracts only manifest-named members with sanitised names (no zip-slip) and refuses newer `format_version`s. `workbook_ui.py` holds the Details, Figures and AVG/VGD dialogs. **Sessions:** a `FileEntry` may carry `members` (files with their path below the session folder); `save` writes them under `data/<id>/<name>/…` (`safe_rel` on every part, `sha256_members` normalised so Windows and `/` paths hash alike), `load` rebuilds the folder tree with a `commonpath` check and `readers.load_file(entry.path)` reopens it; `format_version` is 2 only when a session is present, so ordinary workbooks stay readable by older copies. **Stored results:** `Workbook.cache` (write only) is the HTML browser's payload without figures / cameras / maps (`Workspace._results_cache`, from `_display_for_export`, each `files[]` entry given its file id; switch: Workbook ▸ "Store the parsed results in the workbook", config `cache_in_workbook`, default on) that `save` writes as `cache/spectra.json.gz` (gzip, stored uncompressed in the ZIP) with `cache_version` and `source_files` (id, name, size, sha256) added by `encode_cache`, listed in the manifest under `cache` — **no `format_version` change** (older builds keep an unknown manifest key, find no member and ignore it). A cache over `CACHE_MAX_BYTES` = 64 MB is left out and `save` says so. **The originals stay the only authority: opening still re-parses; the cache is advisory.** `read_cache(path)` → `(payload, "")` or `(None, reason)` and never raises: the manifest must name exactly `CACHE_MEMBER`, the member's sha256 must match, the version must be known, decompression is capped (`CACHE_MAX_JSON`), and the cache's `source_files` must equal the manifest's files. Its only use so far: `htmlbrowser.write_html_from_workbook(book, html)` writes the data-browser page of a saved workbook without loading any instrument file (Workbook ▸ "Data browser from a saved workbook…"; the page says saved figures, holder photo, camera pictures and SnapMaps are not in it). Cost measured: 0.9 s and 1.4 MB for a 2 754-spectrum Avantage experiment, 0.6 s and 0.14 MB for the MXene fits.
- **`exporters.py`** — `export_csv`, `export_vamas` (kinetic-energy abscissa with Intensity + interpolated Transmission, CasaXPS-compatible, real `n_scans`, the fit and metadata blocks), `export_metadata_csv`, `export_metadata_pdf` (reportlab, matplotlib fallback; `_metadata_story(..., look=)` is shared with the report). They use `Region` only, so any loaded format can be exported.
- **`metasummary.py`** — Tk-free tidying of `region_metadata` dicts: `summarise` splits fields into common-to-all vs varying (grouped by value → region labels, numbers ascending), `compact_labels`, `date_range`, `split_columns`. `layout_file` builds the lossless report layout (common block, per-sample line, scan rows with depth levels collapsed only when exact, per-level `strips`) shared by the PDF (`exporters._metadata_story`, portrait A4) and the slides (`pptx_export.py`); `column_weights` sizes its tables. Used by the Details panel for multi-selections (`Workspace._metadata_many`) and by the metadata PDF; the metadata CSV stays flat.
- **`methods.py`** — Tk-free methods text from the dicts of `region_metadata` (`generate(rows, calibration, timing_summary)`): instrument/operator, source and photon energy, X-ray spot, anode voltage / emission, pass energy / step / dwell for surveys vs high-resolution scans (`is_survey`: named so or spanning >250 eV), lens mode and aperture, analyser and acquisition mode, scans, when / how long (`timing_sentence`), neutraliser and ion gun (yes/no words are normalised), depth-profile levels, dates, then the calibration statement (or "not charge-corrected"). Only recorded fields are stated. The user's own text is `details["methods"]` (a `workbook.DETAIL_FIELDS` entry, "" = automatic); `Workspace.methods_generated/methods_text/_report_details` feed it to the report cover, a deck slide, `methods.txt` and the browser. `DetailsDialog` stores "" when the box still equals the generated text.
- **`handover.py`** — the hand-over ZIP, Tk-free: `Part(arc, desc, data|path)`, `spectra_parts` (one VAMAS + one CSV per sample via `exporters`, names made safe/unique), `metadata_parts`, `figure_parts`, `readme_text`, `write_zip` (root folder, README, `SHA256SUMS.txt`, atomic). The report PDF, figure PNGs (`Workspace._figure_pngs`), the browser and the workbook (`Workspace._make_book`, shared with `save_workbook`) need the GUI, so `Workspace.handover_parts` builds them and passes them in.
- **`holder.py`** — Tk-free holder-photo geometry: `stage_to_pixel`/`pixel_to_stage`, `nudged`/`scaled`/`rotated`/`flipped` (what the live `CalibrationPanel` calls), `marker_points`, `nearest` (click-to-select) and `sanitise`. The calibration is stored **per workbook** (`holder.json`, `Workbook.holder`; `Workspace.calib`, part of `_signature`); `~/.spectradeck_calib.json` only seeds new workbooks. `plots.draw_holder_markers` (halo'd markers/labels) + `place_marker_labels` (labels dodge each other and neighbouring markers; call after the layout is final) draw both the photo overlay and the Stage map; clicking a marker calls `Workspace._pick_marker` → `_select_sample`.

### Views and plotting

- **`viewdata.py`** — Tk-free helpers for the alternative views: `energy_axis` (BE ↔ KE per region; kinetic falls back to native when hν is unknown), `resolve_z` / `z_sorted` (z axis of waterfall/heatmap: etch time → level → acquisition time → trace order; all-zero etch times count as absent; acquisition date comes from `SpectrumFile.date_for_region`, because the Kratos `.experiment` reader leaves `Region.date` empty), `build_matrix` (resample onto one grid, NaN outside a trace's range).
- **`panelview.py`** — per-panel view overrides (Tk-free). The view row (view, normalise, offset, z axis, reverse, fit layers) is only the *page default*; a panel (keyed by its group label, so use a per-sample grouping to give two samples' C 1s different views) may override any of those keys in `Workspace.panel_views`, so one page can hold a waterfall, a stack and a fitted spectrum. `VIEWS` = Stack / Waterfall 3D / Heatmap / **Fit** (a stack of one trace with the CasaXPS fit forced on; `Workspace._panel_limit` makes its trace window 1, `_trace_span` sizes the trace slider from the panel whose window slides furthest, no stored fit → plain trace + note). `sanitise` / `sanitise_all` / `resolve` / `with_value` / `reset` / `arrange` (z order for series views, optional reverse for stacks) / `describe`. `Workspace._page_defaults` + `_look_for(key)` are the only readers of the view variables inside `_groups` / `_draw_page` / `_fit_overlay(show)` / click handlers; never read `view_var` etc. per panel directly. Edited by right-clicking a panel (`_panel_menu`, one persistent popup repopulated per click) and reset with `reset_panel_views`. Stored in `capture_state["panel_views"]` (so in every saved figure and the workbook state); `pptx_export.look_notes` lists customised panels. Reports need nothing else: all of them draw through `_render_figure_pages`.
- **`plotstyle.py`** — the plot style, Tk-free: one declarative `FIELDS` tuple (fonts and sizes, line width/style, markers, fill-under, frame, ticks, grid, titles/labels, y-units, energy/intensity ranges, trace labels or legend, export size) is the single source of truth. From it come `sanitise`/`resolve`/`changed` (validation; a style is a full `{key: value}` dict), `BUILTIN_PRESETS` (user presets live in config `plot_presets`), `rc_overrides` (rcParams, layered over the theme by `themes.mpl_rc(pal, style=...)` — always go through `Workspace._rc(pal)`), and the per-panel helpers `plots.py` calls (`line_kwargs`, `panel_titles`, `x_window`/`apply_ranges`, `y_unit`, `note_size`, `label_gutter_points`). `Workspace.plot_style` is stored in config and in `capture_state` (so in the workbook state and in every saved figure; a state without it leaves the live style alone) and is applied by `apply_state`/`_temp_state`, which is how PDF/PPT figure pages get their own look. `plotstyle_ui.PlotStyleDialog` generates its controls from `FIELDS` and applies changes live via `Workspace.set_plot_style`; adding a field means adding it to `FIELDS` and using it in `plots.py`/`rc_overrides`. An energy window is skipped on panels it does not overlap (one C 1s window on a page with O 1s).
- **`themes.py`** — the design tokens: six palettes (`Light` default, `Dark`, `Midnight`, `Solarized Light`, `High contrast`, `System` = native ttk theme), each with chrome colours, plot colours and a colour-blind-safe data palette (`cycle`); WCAG `contrast`/`luminance`, `ramp` (one-hue fade for long stacks), `mpl_rc` (open-frame plots, type scale), `SwatchCache` (tree tick boxes) and `scale_colourmap` / `scale_colours` (user-selectable colour scales; traces are trimmed/nudged to keep contrast ≥ 2 on the plot background) and `with_axis_colour` (frame/tick/label colour override, falls back when contrast < 3), `ThemeManager` (all non-System themes use ttk `clam`). **`fonts.py`** registers the bundled IBM Plex Sans per-OS via ctypes before `tk.Tk()`, applies it to Tk's named fonts and matplotlib, and falls back silently to the system font. **`pdf_preview.py`** — `PdfPreview` frame (PyMuPDF → PPM → `tk.PhotoImage`).
- **`Workspace`** (in `spectradeck.py`) — the single window: Tree | plot | info column in a horizontal `PanedWindow`; the centre is a container that swaps between the plot pane and the `PdfPreview`.
  - **Ticks vs selection:** ticking drives the plot, row *selection* drives Details/Images/Stage map. Ticks are a set of `id(region)` (`Workspace.checked`) so they survive tree rebuilds (filter, theme change, adding/removing files). Tick boxes are `PhotoImage`s on the Treeview rows; a click counts only when `identify_element` reports `"image"`. Redraws go through `_schedule_render` (`after_idle`).
  - **Grouping/stacking:** `group_regions` (by name, ≥50 % x-range overlap, or name per sample / per file) → one panel per group; the pure drawing functions live in `plots.py` (`draw_stack`, `draw_heatmap`, `draw_waterfall3d`, `add_ke_axis`, `norm_factor`, `trace_label`; re-exported by `spectradeck`, so `ee.draw_stack` etc. still work); `draw_stack` draws one spectrum plain or several stacked with an offset and optional normalisation. `view_var` switches each panel to `draw_heatmap` (pcolormesh + colour bar, `heat` ramp per palette) or `draw_waterfall3d` (mplot3d); non-Stack views z-sort each group in `_groups`. `scale_var` / `ke_var` choose the x axis (`add_ke_axis` adds the mirrored top axis); "At cursor" cursors are always stored as binding energy.
  - **View window:** `panels_var` (panels per page) + `panel_start` (row-aligned), `traces_var` + `trace_start` (window over long stacks); wheel / Shift+wheel / scrollbar / slider all just move those two and re-render. Only the visible panels and traces are drawn.
  - **Multiple files:** `Workspace.docs` is a list of readers; `region_parser` maps `id(region)` → its reader (needed for metadata, positions, images, export). `Region.source` labels traces when more than one file is loaded.
  - **Colour = file/sample, tree = legend:** `colour_slots` (one slot per file when several are loaded, else per sample) and `stack_colours` (categorical, or a ramp when a stack shares one slot) are pure functions; `_assign_colours` stores each ticked region's colour in `trace_color`, and `_refresh_boxes` draws that colour as the tree swatch, so tree and plot always agree. `draw_stack` puts end-of-trace labels in a right gutter (`dodge` keeps them apart; the gutter is reserved in `_draw_page`, not by `tight_layout`) and replaces y-ticks on stacks with a scale bar.
  - **Chrome:** one view row (group, normalise, offset), a contextual footer (panels/traces selectors; the scrollbar and trace slider are only packed when they can act, via `_layout_bottom`), a status bar for counts, `Tooltip` for hints, and an info column whose Images / Stage-map notebook only exists when the loaded files have images or positions (`_refresh_info`). The matplotlib toolbar keeps Back/Forward enabled because Windows paints disabled image buttons in the system grey.
  - **Theme:** `set_theme` re-applies ttk styles, rebuilds tick-box images and the tree, recreates the matplotlib toolbar (its icons are recoloured), and updates `matplotlib.rcParams`; PDFs are always drawn inside `rc_context(mpl_rc(PRINT))`.
  - Settings persist in `~/.spectradeck_config.json` (`load_config`/`save_config`); camera calibration in `~/.spectradeck_calib.json` (the files of the former name `~/.escape_explorer_*.json` are read until the first save).
- **`appinfo.py`** / **`splash.py`** / **`about_ui.py`** — the app's identity and first impression. `appinfo` (Tk-free): `NAME`, `VERSION`, `GITHUB_URL` (the profile), `image_path(kind)` (looks for the user's `assets/splash.*`, and an optional smaller `about.*`, which falls back to the splash), `cover_dir` / `cover_images`, `version_report()` / `library_versions()` (never raise). `splash.begin(argv)` is the **first thing `spectradeck.py` does when run as a script** (guarded by `__name__ == "__main__"`, so importing it in tests opens nothing): registers the fonts, makes the one Tk root (`TkinterDnD.Tk` when installed), withdraws it and shows the borderless splash as its Toplevel *before* the matplotlib / readers imports; `splash.status(...)` updates the line under the picture (no-op without one); `main()` takes the root back with `take_root()`, builds `Workspace`, and `finish(root)` deiconifies at once (so `_restore_layout` sees a mapped window) and destroys the splash after `MIN_SECONDS`. Off with `--no-splash` or `cfg["show_splash"]` (Help menu). A missing or unreadable picture gives a text-only card. `set_window_icon` shrinks the picture for `iconphoto`; `set_app_id` gives Windows a taskbar identity. `AboutDialog` shows `small_picture` (≤ 220 px), name, version, the link (`open_link`), library versions, the IBM Plex credit and *Copy version info*.
- **`ribbon.py`** / **`icons.py`** — the tabbed toolbar replacing the old Open / Export / PDF strip. `ribbon.PAGES` is **data** (`(label, icon, target, tip, needs_data)`, dropdowns `("v", label, icon, items, tip, needs)`, `@theme` / `@pane` specials); a target is a `Workspace` method name or `(name, arg, ...)`. `Ribbon` keeps the tab and fold state in `cfg["ribbon_tab"]` / `["ribbon_collapsed"]`, dims `needs_data` buttons while `app.docs` is empty (`Workspace._ribbon_state`, called from `_populate_tree`) and re-applies icons on `set_theme`. Styles `Ribbon.TFrame` / `Ribbon.TButton` / `Ribbon.Toolbutton` / `Tab.Toolbutton` are in `themes._style_clam`. `icons.py` draws ~30 line icons with Pillow on a 24-unit grid at 8x (`ICONS` registry, `draw(name, size, colour, accent)`); `IconCache(palette, size, master)` returns `ImageTk` images (rebuilt in `set_theme`, size scaled by `tk scaling`); `resolve_colour` turns Tk names such as the System theme's `systemwindowtext` into hex. Without Pillow the buttons are text-only. To add a button: an icon function in `icons.py` (decorated `@icon`), an entry in `PAGES`, the method in the menu.

### Reports (PDF, slides, hand-over)

What goes in is one **spec**; the builders lay out the same sections in the same order, and the numbers on the pages come from the same code as the desktop and the HTML page.

- **`reportspec.py`** / **`reportgen_ui.py`** — `reportspec` (Tk-free) holds the **spec**, a plain dict `{"version", "sections": [{"id", "on"}, ...] (this order is the report's order), "skip": {section: [child ids]}, "options": {"sha": "short"|"none", "dividers": "auto"|"none"}, "cover": {...}}`. Children (each saved figure, each file's metadata, each quantified sample, each camera picture / map site) are on unless listed in `skip`, so one added later appears without redoing the choice (`CHILD_KINDS`). `SECTION_DEFS` = cover, contents, summary, **results** ("Quantification"), figures, images ("Camera pictures and SnapMaps"), methods, calibration, metadata, files in the default **results-first** order (audit tables last). `sanitise` makes any input a valid spec (unknown ids dropped, bad options reset, a section an older spec lacks inserted after the one before it in the default order, so an old saved spec gets Contents right after its cover, on); `active(spec, present)` → `[(id, skipped children)]` is what the builders read; `moved` / `with_on` / `with_child` / `with_children` / `with_option` / `with_all` / `with_cover` return new specs; `spec_from_sections(names, "pdf"|"deck")` turns the old `sections=` names into a spec in the old order with no picture, no Contents, no Quantification and no dividers (so `report.SECTIONS` / `pptx_export.SECTIONS` callers are unchanged: PDF "cover" = cover + summary + methods + calibration + files, deck "title" = the first four). Options: `sha` (checksum column of the file list) and `dividers` (`auto` = a divider slide before a section of 5+ slides). `BUILTIN_PRESETS` (Everything, Customer report, Quick look, Audit trail) and `clean_presets` / `all_presets` (a saved preset cannot take a built-in name; **a preset never changes the cover**: it says what goes in, the cover is the user's look). `inventory(...)` → `Inventory` says which sections have content, why not, and their children (`figure_id` = the figure's workbook id else `fig<N>`, `doc_key` = the file's workbook id else its name). `Workspace.report_spec` (config `report_last`; a workbook's own `report.json` replaces it on open and is written on save; part of `_signature`), `report_presets`, `report_inventory()`, `set_report_spec()` (also updates the preview toolbar's ticks), `report_generator()`, `generate_report("pdf"|"pptx"|"both")` (asks for one path, the deck goes beside the PDF, says what was included and any note, offers to open it). `ReportGeneratorDialog` (Workbook ▸ Report generator…, ribbon Report ▸ Generator) keeps its behaviour in plain methods (`toggle_section`, `toggle_child`, `set_children`, `move`, `select_all`, `set_option`, `apply_preset`, `save_preset`, `delete_preset`, `set_cover` / `set_accent` / `choose_picture`) that the click handlers call, so the tests drive it without a mouse; every change is applied to the app at once. A section with more than 6 children starts collapsed; "Items of the selected section: All / None" ticks every child (so 3 of 39 pictures is not 36 clicks); the Options tab has both options; the **Cover** tab is a scrollable list of thumbnails with the design name, "Use my own picture…", six accent swatches + "Other…", the details summary and "Edit details…".
- **`covers.py`** — the cover picture (Tk-free). A cover is `spec["cover"]` = `{"design", "image", "accent"}` (sanitised in `reportspec`; the accent is `#RRGGBB` or "" = navy `#2C3E50`; the default design is `ribbon`). Designs: five built in, drawn by matplotlib (`Figure` + `FigureCanvasAgg`, no pyplot) from the one accent colour and its tints — `ribbon`, `band`, `minimal`, `data` (the ticked survey, else the first ticked spectrum, else the first one loaded: `Workspace.cover_data()`; the ribbon without data), `grid` (peak map) — deterministic (fixed peaks and seed), 14–50 ms each; pictures in `assets/covers/` (`file:<name>`; `README.txt` there) and any browsed file (`image` + path), cropped from the middle to the space and never stretched (Pillow), stored as **JPEG** for the report and slides (a photograph was 1.3 MB as PNG, now ~140 KB) and PNG for the picker's thumbnails (Tk cannot show JPEG); `none`. The splash picture is deliberately not offered (its product name is cut by a 4:1 strip). `art(cover, "pdf"|"pptx", data)` → `Art(data, width, height, unit, note, fmt)`: 180 × 45 mm at the top of the PDF cover (inside the margins, above the letterhead), 13.333 × 1.55 in along the bottom of the title slide; `Art.data` is None (text-only cover) and `Art.note` says why when matplotlib / Pillow is missing or a picture is gone or unreadable. `build_report(..., cover_data=, notes=)` / `build_deck(...)` append the note and `generate_report` shows it instead of dropping the picture silently. Results are cached (design, file path + mtime + size, size, accent, JPEG, data hash).
- **`pdfstyle.py`** / **`report.py`** — the PDF. `pdfstyle.Look` (`accent`, `font`, `bold`, `ink` = the accent darkened 20 % for text and table headers so amber still reads, `tint(t)`) comes from `pdfstyle.look(cover accent)`; the typeface is the bundled IBM Plex Sans registered with reportlab on first use (it has the "α" of "Al Kα", "µ" and "°" that built-in Helvetica lacks; falls back to Helvetica) and `styles(look)` holds the paragraph styles. `exporters._metadata_story(..., look=)` takes it (None = the old navy Helvetica, so the standalone metadata PDF is unchanged). `report.build_report(path, details, logo, file_rows, docs, figures, render_figure, spec=, render_images=, cover_data=, notes=, results=)` builds each part (a run of consecutive reportlab sections — flowing onto the same pages —, the images, the figures) separately and joins them with PyMuPDF. Each flow part records **where its tagged headings landed** (`_mark` on a heading, `_Doc.afterFlowable` reads `self.page`, looking inside `KeepTogether` containers); figures record their first page from what `render_figure` returns (a skipped figure leaves the rest renumbered). **Contents** is its own part built last: `_entries(parts)` → one line per section, and its files / figures / pictures / samples under it when there are two or more, with page numbers from the parts' running start pages; its own page count is settled by rebuilding (a long list runs over). The same entries become the **PDF bookmarks** (`set_toc`, also when Contents is off). The PyMuPDF footer (`_footer`) is the title, the section (`_page_sections`: the last tagged heading at or before the page) and "report page x of y", set in Plex from the file; a cover that leads the report has none. Cover: accent bar, 26 pt title, muted label column; tables are `hAlign="LEFT"` so they line up with the picture. The calibration is not said twice when the methods state it. Figure and image pages are drawn by the caller (`Workspace._report_figure_pages`, `_report_image_pages`) under the print style.
- **`pptx_export.py`** — the 16:9 deck (python-pptx; native tables and text so slides can be restyled; fonts stay Calibri, PowerPoint machine fonts — Plex is not embedded). Slides are built in the spec's order, each noting its section (`_Deck.note`, `content_slide(title, child=)`; `child` names the file or figure a slide starts), then `_assemble` makes the extras and puts everything in place: **divider slides** (`_divider_slide`: full-bleed ink, the section name, its hint and slide count; before a section of `DIVIDER_MIN` slides or more), the **contents** slide(s) (`_entries`, `CONTENTS_ROWS` = 16 a slide; the numbers come from the final `layout`, so they are the real ones, a divider counting as the start of its section) where the spec puts `contents`, moved into place by rewriting the slide id list, then the footer `title | section | n of N` on every slide but the title and the dividers. The accent is the cover's (`_Deck.accent` for the top bar and stripes, `ink` for titles, table headers and the divider background, `alt` = 94 % tint for banding). Figure pictures come from `Workspace._render_figure_pages`, the same renderer the PDF uses (it applies each figure's saved look through `_temp_state` and hands pages to a `consume` callback while the print style is active); a figure slide has an editable caption and speaker notes (`look_notes`). In the deck the calibration rides on the Summary slide, or gets its own when Summary is off. **The look of the divider and contents slides has not been seen** (no slide renderer was available; the deck was checked by reading it back with python-pptx: order, titles, footers, the contents table).
- **`resultspages.py`** — quantification for the PDF and the slides (Tk-free, matplotlib only for the chart). `collect(docs, display, key_of)` reads every region with a CasaXPS fit through `quant.fit_rows(display(r))` into `Results` → `Sample` (key `<doc key>/<sample>`, label = the sample name, else the file name; `notes`) → `Level` (etch level / time, `Depth (nm)` and `Fluence` from the metadata; `entries`, `include`, `res` = `quant.normalise`). Rules, said on the pages: a region name fitted in more than one spectrum at a level counts **once, the dedicated scan (the spectrum named after the region) else the first** (a survey's C 1s does not beat the C 1s scan; the table says "counted once", the notes say which fit counts); an element counted from two lines (`element_of`: Ti 2p and Ti 1s) is counted from both and a note says so — the HTML page leaves both to the user's ticks, the report has no such choice yet (the way out is to leave the sample out); no transmission correction. `composition_cells(level)` (region rows with a state row under each region that has more than one), `profile_axis` (depth → etch time → fluence → level, only when every level has a distinct value), `profile_series` / `profile_cells` (`quant.profile`), `profile_png`. `Results.chosen(skip)` / `notes_for(samples)` (notes belong to samples, so leaving one out leaves its notes out). PDF: `report.results_story` (h1 + method line, per sample a composition table or chart + at % by level table, notes; headings marked so contents / bookmarks list the samples), `report._grid`; deck: `pptx_export._results_slides` (table slides of 15 rows, "depth profile" chart slide + "at % by level" table slides, footnote, method and notes as speaker notes) and `_fit_picture`. `Workspace._results()` (remembered by document identity + `_ann_serial`, which `_ann_changed` bumps) feeds `report_inventory`, `_build_report` and `_build_deck` (`results=`).
- **`imagepages.py`** — camera pictures and SnapMaps as report pages and slides, Tk-free until drawn. `plan(docs, label_of, display, per_sheet, columns, skip)` returns `Page`s (camera sheets first, then one per map site: `kind`, `title`, `n_items`, `draw(fig, rect, cmap)`, lazy `notes()`); `Picture.array()` shrinks to `PICTURE_PX`; the axes keep the full-size picture's pixel coordinates so marker geometry from `snapshot.view_of` is used unscaled; a map site is drawn as an outline (labelled) instead of a marker. `Workspace._image_page_plan/_render_image_pages` draw them under the print style (`_report_image_pages(pdf, skip)` for `report.build_report(..., render_images=)`, `_deck_image_pages(skip)` for `pptx_export.build_deck(..., image_pages=)`: 3 pictures per slide, camera slides as JPEG); offered only when `_has_image_pages()`. **Picking:** `imagepages.items(docs, label_of)` → `[(key, label)]`, keys `cam:<doc key>/<picture name>` and `map:<doc key>/<sample>`, are the children of the Pictures section; `plan(..., skip=)` leaves those out — a picture left out is not drawn beside its map either, and the map page then has no photo. `_build_report` / `_build_deck` hand `reportspec.skipped(spec, "images")` down. A picture's label does not repeat its sample when the name already says it.

### The offline HTML data browser

- **`htmlbrowser.py` + `viewer/`** — `build_payload` turns docs/figures/holder photo into one JSON dict (regular energy axes as `{x0,dx,n}`, intensity to 7 significant digits, metadata, notes, markers, figure PNG and photo as data URIs, holder marker pixels via `holder.marker_points`), `encode_payload` gzips + base64s it, `build_html` inlines `viewer/template.html` + `viewer.css` + `viewer.js` (placeholders `__TITLE__`, `/*__CSS__*/`, `/*__JS__*/`, `__DATA__`; none may appear in the JS) and `write_html` writes it atomically. `viewer.js` has a pure half (decode with `DecompressionStream`, axes, ticks, normalising, grouping, CSV, metadata summary; exported for Node) and a page half (canvas plots, tree, tabs, holder) that only runs where there is a `document`; it never uses `innerHTML`/`eval` and makes no network requests (both asserted by tests). Features of the page: filterable sample tree, stack / overlay / normalise, BE ↔ KE, depth-level slider (◀ ▶ Play, ← / → keys, ignored inside form controls), saved figures with captions, metadata / notes / methods tabs (`build_notes` at the top of Notes), holder photo with markers, CSV, light / dark / print styles, a "Read-only" badge. Every panel has a **PNG** button (`savePanelPng`: drawn again off screen through the same `drawPanel`, light colours, 2x); **Download everything** builds a store-only ZIP in the page (`V.zip` / `V.crc32` / `V.utf8`, tested by writing it from Node and reading it back with Python's `zipfile`) from `V.bundleFiles` (README.txt, quantification.csv, methods.txt, calibration.txt, summary.txt and one CSV per sample and spectrum name with all depth levels side by side). **No absolute paths leave the app:** `htmlbrowser.scrub_paths` cuts drive-letter, UNC and `/home`-style paths in every metadata value down to the file or folder name (`_meta`).
  - **Camera images and SnapMaps** (Avantage): `build_payload(..., cameras=True, snapmaps=True)` adds `cameras` (each calibrated picture shrunk to 800 px JPEG via Pillow, with `points` / `maps` outlines already in the shrunk pixels, `bar_px` for 1 mm; skipped with a note when Pillow is missing, 40 MB budget) and `maps` (`pack_cube`: counts as uint16 steps of `MAP_STEP` = 1/8 (coarser only if max/65535 is larger), zlib, base64, `[iy][ix][channel]`; `pack_maps` sums 2 then 4 energy channels, then drops trailing maps, to fit `MAP_BUDGET` = 40 MB, and `build_notes` says so; each map carries its `region` id, the spectrum carries `map`, and `cam = {id, ext}` gives the picture's edges in the map's own µm). `viewer.js` pure half: `decodeMap` (DecompressionStream `deflate`), `mapImage`, `meanSpectrum`, `rectMask`, `pixelAt`, `defaultWindow`, `colourRange`, `scaleColour` / `SCALES` (anchor colours, close to matplotlib), `mapCsv`, all checked in `tests/viewer_test.js` against `snapmap.py` on the same map (map values are multiples of 1/8 in the fixture so quantisation is exact); page half: `paintMarkers` (shared with the holder photo), `withPicture`, `redrawTab`, `followSelection`, `drawCamera`, `drawMapView` / `drawSpectrum`.
  - **CasaXPS fits** (`htmlbrowser._fit_block`): a region with `Region.fit` gets `fit = {rows, notes}`; each row is `quant.fit_rows(display_region, curves=True)` plus `curve = {i0, bg, env, comps}` — `casafit.curves` output from the region's first point on, in the spectrum's own counts, 6 significant figures, so the page draws exactly what the desktop draws and reconstructs nothing (residual = y − env in the page). `FIT_BUDGET` (600 000 values) drops curves, never the table, with a `build_notes` line. `viewer.js`: pure `fitRows` / `curveFull` / `fitStates` / `residual` / `fitCsvColumns` (`buildCsv` adds the fit columns named as `exporters.fit_columns` names them; checked against `export_csv`), page `drawFit` (background dashed, components filled on it, envelope, residual band at true scale under the data), `fitLegend` (≤ 6 states), `updateFitBox` (per-component table with show ticks), toggles in `#fitbar`; only on panels showing one spectrum, like the desktop.
  - **Quantification and depth profiles in the page** mirror `quant.py` (`viewer.js` `quantGroups` / `quantNormalise` / `quantStates` / `quantTable` / `quantCsv` / `V.profile`, compared with it in `viewer_test.js`). The **Quantification tab** (`renderQuant`) lists each sample's fitted regions with a tick to include/exclude (a region that appears twice, e.g. from a survey and its own scan, is the user's call), chemical-state rows under each, a depth-level select, the transmission checkbox (disabled when no row has `area_t`) and `quantification.csv`. The **Depth profile tab** (`renderDepth`, shown when a sample has ≥ 2 distinct levels) adds `peakMaxSeries` (needs no fit — the only mode for Avantage data), `levelInfo` (level, etch time, and the `Depth (nm)` / `Fluence (ions/cm²)` values the desktop writes into the region metadata from the sputter settings) and `profileAxes` (depth → etch time → fluence → level; an axis is offered only when all levels have distinct values, so all-zero etch times fall back to the level number; a note says to enter the etch rate for depth); the chart, table and `depth_profile.csv` use the ticks and the transmission choice of the Quantification tab, and clicking a point opens that level in the Spectra tab (`gotoLevel`).
  - **Element identification:** `build_payload(..., lines=None)` ships `elements = element_table(lines)` (the `xpslines` table as `[element, line, be, ke, rank]`, an Auger line has `ke` and no `be`; `common`, `bonus`, default `hv`) and, on every binding-energy spectrum wider than `SURVEY_SPAN` (250 eV), `auto` = `xpslines.auto_label` on the spectrum *as shown* (so labels follow a BE shift). `viewer.js` `V.candidates` ports `xpslines.candidates` (same ordering, tested against it, including Auger lines and the hν default). The page's **Identify peaks** mode (`S.ident`, `identifyAt`, `renderIdBox`): a click (not a drag) on a panel lists the lines within ± a window of the peak as chips; a chip adds a session-only label (`ident.extra[spec id]`, cleared with a button — the workbook's own labels come from the payload's `markers`). `Label survey peaks` (`ident.auto`, default **off**: the automatic labels use approximate line positions and can be wrong) draws `auto`. `panelMarks(group)` draws the markers of **every** spectrum of a panel (deduplicated by label and 0.5 eV), each with its own hν; when labels crowd, the user's own are drawn first, then the app's, then automatic ones, and a label within 11 px of one already drawn loses its text but keeps its line.
  - **Tests:** `tests/viewer_test.js` (run by `test_htmlbrowser.py` when Node is installed) checks the JS against numbers computed by Python (decoded data, `norm_factor`, `themes.ramp`, `export_csv`, the maps, the fit columns, the quantification). Check UI changes in the in-app browser: `.claude/launch.json` running `python -m http.server` over a folder holding a generated page (files outside the project render as static snapshots, so serve over HTTP), then screenshots and console errors, desktop and phone width.

## Verifying

- **A reader** is validated against **the same data in another format**, never by eye: a text export next to a binary file (`.vgd` ↔ `.avg`), or a vendor's own VAMAS export (`.spe`, `.kal`, `.avg` ↔ `.vms`). Compare energy arrays, counts (allowing documented factors such as dwell time or transmission), hν, pass energy, dwell and positions. Beware that a partner export can itself be wrong (a Casa VAMAS of the Scienta `.txt` has a reversed axis) — check physics (peak positions) before "fixing" a reader to match it. To exercise the GUI without instrument files, monkeypatch `EscapeParser.load` (or a reader's `load`) to fill `regions` and call `_build_tree()` on synthetic `Region`s.
- **Reports:** build one from synthetic files (see `tests/test_pdfreport.py`, `test_deckdesign.py`, `test_results.py`, whose helpers build documents and fit rows without instrument data), render the PDF pages with PyMuPDF to look at them, and read a deck back with python-pptx. Slides cannot be rendered here.
