# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

eXPoSe SpectraDeck: a single-window Tkinter app that browses, plots and exports XPS spectra from many instruments — Kratos ESCApe (`.experiment`) and Vision (`.kal`), VAMAS (any vendor), Thermo Avantage (`.avg`/`.vgd`/`.avx`), PHI MultiPak (`.spe`), Scienta SES (`.txt`) — to CSV or VAMAS. See `README.md` for the user-facing tour.

## Commands

```bash
python launch.py                # create ./.venv, install deps, start the app (python3 on macOS/Linux)
python launch.py --setup-only   # build the venv without starting the app
python launch.py --reinstall    # rebuild the venv from scratch
python launch.py --check        # report venv / tkinter / app-file status
python spectradeck.py       # run directly with the current interpreter
python -m unittest discover tests            # unit tests (synthetic files, no instrument data needed; includes palette contrast/separation and colour-rule tests)
XPS_CORPUS=<folder> python -m unittest tests.test_corpus   # every recognised file in a folder must load
```

There is no linter or build step. Dependencies (`matplotlib`, `pillow`, `reportlab`, `pymupdf`) are in `requirements.txt`; `launch.py` keeps a `REQUIRED` fallback list that must stay in sync and re-installs when the requirements file's SHA-1 changes. `tkinter` comes from the base Python, not the venv. The app must still start when matplotlib / Pillow / PyMuPDF are missing (`HAVE_MPL`, `HAVE_PIL`, `pdf_preview.HAVE_PDF`).

## Architecture

`spectradeck.py` is the entry point (window, dialogs, `main()`); the application name lives in `appinfo.NAME` ("eXPoSe SpectraDeck", formerly "ESCApe Explorer" — use the constant, never a literal; `tests/test_appname.py` enforces it); everything else is a module beside it:

- **`readers/`** — one reader per format behind `readers.load_file(path)`. `readers/__init__.py` holds the `READERS` registry and picks a reader by **content sniffing** first (extension is only a hint), so renamed files still open; add a format by writing a `SpectrumFile` subclass with a `sniff(head, ext)` function and registering it there (this also feeds the Open dialog filters).
  - `readers/base.py`: `Region` / `TreeNode` / `ImageBlob` dataclasses and the `SpectrumFile` base class. A reader only fills `regions` (+ `instrument`, optional `depth_profile`, `_sample_pos`, `images`) and calls `_finish()`; the tree, per-region metadata and positions then come from the base class. Shared helpers: `canon_region_name` ("C1s" → "C 1s", surveys → "Survey", so the same core level groups across formats), `guess_region_name` (a "core level" on a >250 eV axis is a survey), `kv_from_lines`, `read_bytes` (always use it — never leave file handles open).
  - `Region.energy` is **binding energy** for XPS whenever the photon energy is known (BE = hν − KE, as CasaXPS does); otherwise the native axis is kept and `energy_label` says so (only "Binding…" axes are inverted when plotted).
  - `vamas.py`: field-by-field ISO 14976 parser. Header layout varies by experiment mode (e.g. `SDPSV` has no "number of spectral regions"), so `load()` tries the expected layout then alternatives; numbers between the source label and analyser mode are read by type because the count varies by mode; `IRREGULAR` scans have no start/step (the first corresponding variable is the abscissa).
  - `thermo_avg.py` defines `DataSpace` and `ThermoDataSpaceFile._from_dataspace`, shared with `thermo_vgd.py` (pure-Python OLE2 in `ole2.py`, no `olefile`). `.vgd` property ids → `DS_*` names are the `PID_NAMES` table; the axis stream is decoded by anchoring on the expected item counts, and the **axis type code** is the int32 right after each axis's linear flag (1 ENERGY, 3 X, 4 Y, 6 ETCHLEVEL, 8 ETCHTIME, 10 POSITION: `AXIS_CODES`). `dataspace_kind(ds)` classifies a DataSpace as `spectrum` / `position` (one spectrum per analysis point) / `levels` (depth profile; etch time from the ETCHTIME axis) / `map` (SnapMap) / `image` (camera picture: value type 13, one packed **B<<16|G<<8|R** float per pixel, checked pixel for pixel against Avantage's PNG export; the `.vgd` reader leaves `VGData` unread and the PNG is made by `ImageBlob.loader` on demand) / `table` (auto-height Z values: `value_table`, no regions; the `.avg` dump does not list per-point X/Y there) / `other`. Both readers must stay identical on every pair (validated on 146 `.vgd`/`.avg` pairs). A DataSpace with no axes raises "this DataSpace is empty" (an aborted acquisition). A SnapMap `.vgd` is handed over as raw doubles (`DataSpace.raw`, ~0.1 s) rather than per-pixel lists.
  - `thermo_vgx.py` parses an Avantage `.VGX` (OLE2 of MFC objects; only the `FF FE FF`-prefixed UTF-16 strings are read): experiment / project / platter / date folder from the root, then group (source configuration, e.g. "X-Ray005 200um - FG  ON") → sample → step nodes ordered by their `Embedding N` numbers (= run order). A sample node's own strings list its scans differently per scan type, so they are only matched against folder names. `thermo_experiment.ThermoExperiment` opens a **folder or a `.VGX`** as one `SpectrumFile` (`readers.load_file(path, progress=)`; `looks_like_experiment`, `find_vgx` looks up to 4 levels above a folder): sample = the folder below the configuration, `Region.sample` = "<sample> <Pt #001a>" for multi-point scans, `.vgd` preferred over `.avg`, `errors` / `skipped` collected without stopping, `members` = every file used (for the workbook), custom `_build_tree` (experiment → `samplegroup` → `sample` → scans; depth-profile samples use `regionfolder` levels; duplicate core levels get the scan name). Camera images become `ImageBlob`s (`fmt="png"`, `calib`, `sample`, label time from the file name because stored times are UTC).
  - `phi_spe.py` (16-byte preamble, all 96-byte block headers, then float64 blocks; counts/s), `scienta_txt.py`, `kratos_kal.py`, `kratos_experiment.py` (the original reverse-engineered `EscapeParser`).
- **`snapmap.py`** / **`snapmap_ui.py`** — `MapCube` (float32 `array` `[iy][ix][channel]`, `x0/dx/y0/dy` in µm in the *image* frame, `stage_x_mm/stage_y_mm`), attached as `Region.extra["cube"]` beside the summed-spectrum region; numpy only inside `image` / `roi_spectrum` / `rect_mask` / `default_window` / `colour_range`. `default_window` takes a sloping baseline off, ignores the outer tenth, favours the middle and enforces ≥ 2 eV (weak Cu 2p peaks fooled simpler rules). `SnapMapDialog` (energy window by `SpanSelector`, ROI by `RectangleSelector`, element switch, overlay on the nearest camera image, PNG/CSV export) opens from Tools, the tree context menu or a double-click (`Workspace.open_snapmap`).
- **`snapshot.py`** — camera-image geometry from `ImageBlob.calib`: `stage_to_pixel` / `pixel_to_stage` / `markers` / `map_rectangle` / `nearest_image`. **Measured** on K-Alpha+ (registering neighbouring photos, r 0.53–0.80 vs < 0.3 for the other sign choices): image x runs *against* stage X, image y *with* stage Y (`X_DIR`, `Y_DIR`); a SnapMap's own axes follow the image (they overlay the photo without a flip) and are centred on its stage position. `Workspace._render_snapshot` draws it (used instead of the holder-photo overlay for calibrated images); thumbnails are filled one per `after` tick (`_fill_thumbs`). `view_of(calib, positions, sites)` returns the points and map outlines inside a picture (used by the HTML browser and the report pages).
- **`imagepages.py`** — camera pictures and SnapMaps as report pages and slides, Tk-free until drawn. `plan(docs, label_of, display, per_sheet, columns)` returns `Page`s (camera sheets first, then one per map site: `kind`, `title`, `n_items`, `draw(fig, rect, cmap)`, lazy `notes()`); `Picture.array()` shrinks to `PICTURE_PX`; the axes keep the full-size picture's pixel coordinates so marker geometry from `snapshot.view_of` is used unscaled; a map site is drawn as an outline (labelled) instead of a marker. `Workspace._image_page_plan/_render_image_pages` draw them under the print style (`_report_image_pages(pdf)` for `report.build_report(..., render_images=)`, `_deck_image_pages()` for `pptx_export.build_deck(..., image_pages=)`: 3 pictures per slide, camera slides as JPEG); sections `"images"` sit between metadata and figures in both, and are offered only when `_has_image_pages()`.
- **`viewdata.py`** — Tk-free helpers for the alternative views: `energy_axis` (BE ↔ KE per region; kinetic falls back to native when hν is unknown), `resolve_z` / `z_sorted` (z axis of waterfall/heatmap: etch time → level → acquisition time → trace order; all-zero etch times count as absent; acquisition date comes from `SpectrumFile.date_for_region`, because the Kratos `.experiment` reader leaves `Region.date` empty), `build_matrix` (resample onto one grid, NaN outside a trace's range).
- **`panelview.py`** — per-panel view overrides (Tk-free). The view row (view, normalise, offset, z axis, reverse, fit layers) is only the *page default*; a panel (keyed by its group label, so use a per-sample grouping to give two samples' C 1s different views) may override any of those keys in `Workspace.panel_views`, so one page can hold a waterfall, a stack and a fitted spectrum. `VIEWS` = Stack / Waterfall 3D / Heatmap / **Fit** (a stack of one trace with the CasaXPS fit forced on; `Workspace._panel_limit` makes its trace window 1, `_trace_span` sizes the trace slider from the panel whose window slides furthest, no stored fit → plain trace + note). `sanitise` / `sanitise_all` / `resolve` / `with_value` / `reset` / `arrange` (z order for series views, optional reverse for stacks) / `describe`. `Workspace._page_defaults` + `_look_for(key)` are the only readers of the view variables inside `_groups` / `_draw_page` / `_fit_overlay(show)` / click handlers; never read `view_var` etc. per panel directly. Edited by right-clicking a panel (`_panel_menu`, one persistent popup repopulated per click) and reset with `reset_panel_views`. Stored in `capture_state["panel_views"]` (so in every saved figure and the workbook state; `apply_state` treats a missing key as **none**, unlike the other keys, so an old figure never inherits the live overrides); `pptx_export.look_notes` lists customised panels. Reports need nothing else: all of them draw through `_render_figure_pages`.
- **`metasummary.py`** — Tk-free tidying of `region_metadata` dicts: `summarise` splits fields into common-to-all vs varying (grouped by value → region labels, numbers ascending), `compact_labels`, `date_range`, `split_columns`. `layout_file` builds the lossless report layout (common block, per-sample line, scan rows with depth levels collapsed only when exact, per-level `strips`) shared by the PDF (`exporters._metadata_story`, portrait A4) and the slides (`pptx_export.py`); `column_weights` sizes its tables. Used by the Details panel for multi-selections (`Workspace._metadata_many`) and by the metadata PDF (`exporters._sample_block`); the metadata CSV stays flat.
- **`workbook.py`** — the `.xpscontainer` experiment workbook (Tk-free): a ZIP of JSON (`manifest`, `workbook` details, `state` = the current look, `figures`, `metadata` snapshot) plus the original data files verbatim under `data/<id>/`. Data are re-parsed through `readers.load_file` on open; ticked spectra are stored as `region_ref`s (file id + position + name/sample/etch level) and found again with `resolve_refs`, because `id(region)` is not stable. `save` writes a temp file then `os.replace`; `load` extracts only manifest-named members with sanitised names (no zip-slip) and refuses newer `format_version`s. **Sessions:** a `FileEntry` may carry `members` (files with their path below the session folder); `save` writes them under `data/<id>/<name>/…` (`safe_rel` on every part, `sha256_members` normalised so Windows and `/` paths hash alike), `load` rebuilds the folder tree with a `commonpath` check and `readers.load_file(entry.path)` reopens it; `format_version` is 2 only when a session is present, so ordinary workbooks stay readable by older copies. `Workspace.capture_state` / `apply_state` / `_temp_state` (in `spectradeck.py`) convert to and from the Tk variables — keep them in step with any new view setting (they mirror `_on_close`); `workbook_ui.py` holds the Details, Figures and AVG/VGD dialogs. **`report.py`** builds the customer report (reportlab cover + metadata, matplotlib figure pages via `Workspace._report_figure_pages`, merged and footed with PyMuPDF). **`pptx_export.py`** builds the 16:9 deck (title, summary, data files, metadata tables, one slide per figure page with caption + speaker notes) with python-pptx; figure pictures come from `Workspace._render_figure_pages`, the same renderer the PDF report uses (it applies each figure's saved look through `_temp_state` and hands pages to a `consume` callback while the print style is active). **`annotations.py`** holds user edits *beside* the data (display names, notes, metadata edits, BE shifts, peak markers, calibration log) keyed by workbook file id + sample / region name / position, stored in the workbook (`annotations.json`) and never applied to the readers' output: `SpectrumFile.annotations`/`file_id` let `region_metadata` / `samples_metadata` apply them, and `Workspace._display(region)` returns a shifted/renamed copy (the photon energy moves with a BE shift, so kinetic energies are unchanged) that drawing (`_draw_page`), exports (`_write_export`) and reports use — call `_ann_changed()` after any change. `calibration.py` (peak finding, statement), `xpslines.py` + `assets/xps_lines.json` (element lines, candidate lookup, auto-label). Plot clicks are routed through `_click_cb` (Identify) / `_pick_cb` (one-shot, Calibrate) before the 'At cursor' handler. **`importplan.py`**: `find_pairs` / `apply_choice` for `.avg` + `.vgd` copies of one dataset (`Workspace._resolve_duplicate_formats`, config key `dup_format`).
- **`exporters.py`** — `export_csv`, `export_vamas` (kinetic-energy abscissa with Intensity + interpolated Transmission, CasaXPS-compatible), `export_metadata_csv`, `export_metadata_pdf` (reportlab, matplotlib fallback). They use `Region` only, so any loaded format can be exported.
- **`plotstyle.py`** — the plot style, Tk-free: one declarative `FIELDS` tuple (fonts and sizes, line width/style, markers, fill-under, frame, ticks, grid, titles/labels, y-units, energy/intensity ranges, trace labels or legend, export size) is the single source of truth. From it come `sanitise`/`resolve`/`changed` (validation; a style is a full `{key: value}` dict), `BUILTIN_PRESETS` (user presets live in config `plot_presets`), `rc_overrides` (rcParams, layered over the theme by `themes.mpl_rc(pal, style=...)` — always go through `Workspace._rc(pal)`), and the per-panel helpers `plots.py` calls (`line_kwargs`, `panel_titles`, `x_window`/`apply_ranges`, `y_unit`, `note_size`, `label_gutter_points`). `Workspace.plot_style` is stored in config, in `capture_state` (so in the workbook state and in every saved figure; a state without it leaves the live style alone) and is applied by `apply_state`/`_temp_state`, which is how PDF/PPT figure pages get their own look. `plotstyle_ui.PlotStyleDialog` generates its controls from `FIELDS` and applies changes live via `Workspace.set_plot_style`; adding a field means adding it to `FIELDS` and using it in `plots.py`/`rc_overrides`. An energy window is skipped on panels it does not overlap (one C 1s window on a page with O 1s).
- **`holder.py`** — Tk-free holder-photo geometry: `stage_to_pixel`/`pixel_to_stage`, `nudged`/`scaled`/`rotated`/`flipped` (what the live `CalibrationPanel` calls), `marker_points`, `nearest` (click-to-select) and `sanitise`. The calibration is stored **per workbook** (`holder.json`, `Workbook.holder`; `Workspace.calib`, part of `_signature`); `~/.spectradeck_calib.json` only seeds new workbooks. `plots.draw_holder_markers` (halo'd markers/labels) + `place_marker_labels` (labels dodge each other and neighbouring markers; call after the layout is final) draw both the photo overlay and the Stage map; clicking a marker calls `Workspace._pick_marker` → `_select_sample`.
- **`methods.py`** — Tk-free methods text from the dicts of `region_metadata` (`generate(rows, calibration)`): instrument/operator, source and photon energy, pass energy / step / dwell for surveys vs high-resolution scans (`is_survey`: named so or spanning >250 eV), lens mode and aperture, neutraliser and ion gun (yes/no words are normalised), depth-profile levels, dates, then the calibration statement (or "not charge-corrected"). Only recorded fields are stated. The user's own text is `details["methods"]` (a `workbook.DETAIL_FIELDS` entry, "" = automatic); `Workspace.methods_generated/methods_text/_report_details` feed it to the report cover, a deck slide, `methods.txt` and the browser. `DetailsDialog` stores "" when the box still equals the generated text.
- **`handover.py`** — the hand-over ZIP, Tk-free: `Part(arc, desc, data|path)`, `spectra_parts` (one VAMAS + one CSV per sample via `exporters`, names made safe/unique), `metadata_parts`, `figure_parts`, `readme_text`, `write_zip` (root folder, README, `SHA256SUMS.txt`, atomic). The report PDF, figure PNGs (`Workspace._figure_pngs`), the browser and the workbook (`Workspace._make_book`, shared with `save_workbook`) need the GUI, so `Workspace.handover_parts` builds them and passes them in.
- **`htmlbrowser.py` + `viewer/`** — the offline HTML data browser. `build_payload` turns docs/figures/holder photo into one JSON dict (regular energy axes as `{x0,dx,n}`, intensity to 7 significant digits, metadata, notes, markers, figure PNG and photo as data URIs, holder marker pixels via `holder.marker_points`), `encode_payload` gzips + base64s it, `build_html` inlines `viewer/template.html` + `viewer.css` + `viewer.js` (placeholders `__TITLE__`, `/*__CSS__*/`, `/*__JS__*/`, `__DATA__`; none may appear in the JS) and `write_html` writes it atomically. `viewer.js` has a pure half (decode with `DecompressionStream`, axes, ticks, normalising, grouping, CSV, metadata summary; exported for Node) and a page half (canvas plots, tree, tabs, holder) that only runs where there is a `document`; it never uses `innerHTML`/`eval` and makes no network requests (both asserted by tests). `tests/viewer_test.js` (run by `test_htmlbrowser.py` when Node is installed) checks the JS against numbers computed by Python (decoded data, `norm_factor`, `themes.ramp`, `export_csv`). Check UI changes in the in-app browser: `.claude/launch.json` running `python -m http.server` over a folder holding a generated page (files outside the project render as static snapshots, so serve over HTTP), then screenshots and console errors. **Camera images and SnapMaps** (Avantage): `build_payload(..., cameras=True, snapmaps=True)` adds `cameras` (each calibrated picture shrunk to 800 px JPEG via Pillow, with `points` / `maps` outlines already in the shrunk pixels, `bar_px` for 1 mm; skipped with a note when Pillow is missing, 40 MB budget) and `maps` (`pack_cube`: counts as uint16 steps of `MAP_STEP` = 1/8 (coarser only if max/65535 is larger), zlib, base64, `[iy][ix][channel]`; `pack_maps` sums 2 then 4 energy channels, then drops trailing maps, to fit `MAP_BUDGET` = 40 MB, and `build_notes` says so; each map carries its `region` id, the spectrum carries `map`, and `cam = {id, ext}` gives the picture's edges in the map's own µm), with `build_notes` shown by `export_html_browser`. **CasaXPS fits** (`htmlbrowser._fit_block`): a region with `Region.fit` gets `fit = {rows, notes}`; each row is `quant.fit_rows(display_region, curves=True)` (numbers as above, components with `be`/`fwhm`/`area`/`shape`/`state`/`gk`) plus `curve = {i0, bg, env, comps}` — `casafit.curves` output from the region's first point on, in the spectrum's own counts, 6 significant figures, so the page draws exactly what the desktop draws and reconstructs nothing (residual = y − env in the page). `FIT_BUDGET` (600 000 values) drops curves, never the table, with a `build_notes` line. `viewer.js`: pure `fitRows` / `curveFull` / `fitStates` / `residual` / `fitCsvColumns` (`buildCsv` adds the fit columns named as `exporters.fit_columns` names them; checked in `viewer_test.js` against `export_csv`), page `drawFit` (background dashed, components filled on it, envelope, residual band at true scale under the data), `fitLegend` (≤ 6 states), `updateFitBox` (per-component table with show ticks), toggles in `#fitbar`; only on panels showing one spectrum, like the desktop. `viewer.js` pure half: `decodeMap` (DecompressionStream `deflate`), `mapImage`, `meanSpectrum`, `rectMask`, `pixelAt`, `defaultWindow`, `colourRange`, `scaleColour` / `SCALES` (anchor colours, close to matplotlib), `mapCsv`, all checked in `tests/viewer_test.js` against `snapmap.py` on the same map (map values are multiples of 1/8 in the fixture so quantisation is exact); page half: `paintMarkers` (shared with the holder photo), `withPicture`, `redrawTab`, `followSelection`, `drawCamera`, `drawMapView` / `drawSpectrum`.
- **`quant.py`** — quantification from CasaXPS fits (Tk-free, numpy only to evaluate). `fit_rows(display_region, curves=False)` gives one JSON-ready row per distinct fit region (`casafit.distinct_regions`; `Curves.fit_region` carries the `FitRegion`): RSF, region **area = ∫(data − background) in counts/s·eV** (dwell × scans divided out, the scale of the stored component areas — checked: ∫ of each reconstructed component = its stored area; where the background is not reproduced it falls back to Σ components, `basis`), `area_t` with the transmission function divided out (only when the file has one; **off by default** in `normalise(..., transmission=)` because it is unknown whether CasaXPS applies it to Kratos data), region limits and component positions in the *drawn* BE frame (`hν_display − (pos_ke + shift_of_comps)`), and per component the chemical-state key/name (`state_of`: INDEX ≥ 0 shares a state, a group tag equal to the region's name is not a name — the rule `plots.draw_fit` uses). `normalise(rows, include)` → at % = area/RSF over the included rows (rows with no RSF/area say why), `states(row, at)` splits an element, `csv_rows(groups, include, transmission)` is the quantification table (one group per sample and depth level, each normalised on its own; the page writes the identical table — `viewer.js` `quantGroups` / `quantNormalise` / `quantStates` / `quantTable` / `quantCsv`, compared with it in `viewer_test.js`). The page's **Quantification tab** (`renderQuant`) lists each sample's fitted regions with a tick to include/exclude (a region that appears twice, e.g. from a survey and its own scan, is the user's call), chemical-state rows under each, a depth-level select, the transmission checkbox (disabled when no row has `area_t`) and `quantification.csv`. Checked on the vanadium example (96 and 25 scans, two overlapping C 1s regions). The other program's (XPSView / HarwellXPS) quantification tab divides by dwell only, counts overlapping regions twice and merges all INDEX −1 components, so its numbers are not a reference.
- **`sputter.py`** / **`sputter_ui.py`** — per-sample ion gun settings (ion, charge, energy, current + unit, raster, etch rate + unit; `sanitise` fills a full dict, unknown stays `None`), `fluence = I·t/(q·e·A)`, `depth_nm`, `missing(mode, s)` (what to enter), `from_text` ("5 keV Ar+") / `from_properties` (Avantage `...IONGUN...` keys: text and eV-keyed energy only — a unit is never guessed) / `merge_prefill`. Stored in `Annotations.sputter` (sample key → settings) and applied in `apply_metadata` (per depth level: ion, energy, current, raster, rate, `Depth (nm)`, `Fluence`), so `methods._beam_sentence` and the HTML browser see them. `viewdata.Z_MODES` gained `Depth` and `Fluence` (`resolve_z/z_sorted(..., sputter_for)`; judged on their own values, not on etch-time distinctness) and `z_unavailable` writes the "enter X" notes shown by `_draw_page`. Readers set `SpectrumFile.sputter_hint` (Kratos: the `N keV Ion+` string in the etch settings; PHI: kv keys; Avantage: properties) and `sputter_prefill()` merges it with the `Ion gun / sputtering` text. `Workspace.sputter_samples/get/set/prefill` serve the dialog.
- **`vamasmeta.py`** — metadata carried in VAMAS comments (Tk-free): `encode(md)` / `decode(lines)` write and read a `=== <app name> metadata ===` … `=== end of … ===` block of `key: value` lines (characters beyond Latin-1 are escaped as a backslash-u sequence, a literal backslash before "u" is doubled; the former app name's marker is still read). `EXPERIMENT_KEYS` go in the header comment, everything else in each block comment. `apply_to_region` restores name / anode / power / technique / date / position / etch level and time / lens / aperture / quality and keeps the rest in `Region.extra["preserved_metadata"]`, which `SpectrumFile.region_metadata` merges (never over a non-empty computed value). `VAMAS_OWN` (photon energy, pass energy, dwell, step, points, BE range) is never taken from the text. `exporters.export_vamas(..., metadata=[one dict per region], experiment_metadata=)` writes it (the file is now Latin-1; photon energy, abscissa start and step to 10 significant digits); `Workspace._write_export` and `handover.spectra_parts` pass `parser.region_metadata`. `readers/vamas.py` restores it and rebuilds the sputter prefill (`_restore_sputter`). Validated by exporting and re-reading real Kratos `.kal` / `.experiment` and Avantage `.avg` files: every metadata key comes back except values the source never had.
- **`lineshapes.py`** / **`casafit.py`** — CasaXPS fits from VAMAS (numpy needed only to evaluate). `casafit.parse(comment_lines)` → `Fit` (`FitRegion`s with the six numbers after the averaging width as `params`, `FitComponent`s with INDEX group, `calib_shift` = Σ(A − M) of `Calib` lines, `lines`, and `block` = the whole CasaXPS section of the comment **verbatim**, which is what `to_lines` writes back so CasaXPS reopens its own fit). `casafit.calibration(comment_lines)` → `Calib` (`shift`, `measured`, `assigned`, `region_shift`, `comp_shift`) is independent of the fit, so a block with a `Calib` line and no fit keeps its correction. `readers/vamas.py` sets `Region.fit` per block (a depth profile has one per block) plus `extra["comment_lines"]` and `extra["n_scans"]`. **Frames** (validated on real files, see `tests/test_casafit.py` and `tests/test_casacalib.py`): region limits and component positions are KE; a `Calib` line **without** the `Regions` / `Comps` flags means they are in the *calibrated* frame (raw KE = position + shift, raw BE = hν − position − shift), **with** the flags CasaXPS moved them with the spectrum and they are raw KE (`Fit.shift_of_regions/_of_comps` return the shift to add; each flagged line drops out of its own sum). `curves` works on raw KE only. Intensity is counts/s, so curves are multiplied by dwell × scans to match `Region.counts`. Because everything is anchored in KE, `_display` (which moves hν with a BE shift) needs no fit handling. `casafit.curves` returns `Curves` aligned with the spectrum's points (NaN outside the region, `residual_rms`, `approximate`, `scale_known`, `background_known`); overlapping regions with one name collapse to the widest (`distinct_regions`); an unreproduced background gives components but no envelope. `lineshapes`: `GL`/`SGL` exact; `LA`/`LF` are reconstructions (`GAUSS_K` from earlier calibration on Harwell data; a sweep on the six real fits found no better value beyond noise — do not retune on so few); Shirley (iterative, `avg`-point end levels), linear and **`U 2 Tougaard`** (`tougaard_u2`: `K(T) = B T / (C + T²)²` summed over the data above each point, anchored at the mean of the last `avg` points; B = `params[2]`, C = |`params[3]`| because CasaXPS stores C negative — residual 2–5 % of the range on 16 real MXene regions); other Tougaard types return None. `plots.draw_fit` overlays it on single-spectrum panels (`draw_stack(..., fit=)`; the legend names a group by its tag unless that is just the region's name, and lists over six entries go below the axes); `Workspace._fit_overlay` + `fit_vars` (Components / Envelope / Background toggles, in config and in `capture_state` as `fit_show`). `exporters.export_vamas` writes `to_lines(r.fit)` first in the block comment and the real scan count; `export_csv` adds `fit_columns`; `region_metadata` gets a "CasaXPS fit" line. The fit is read-only: never edited or refitted.
- **CasaXPS charge correction on the region** — `Region.calibration_shift` (eV, binding axes only) is what the file itself says to add; `extra["casa_calib"]` holds `measured` / `assigned` / `shift` / `inherited`. `readers/vamas.py` (`_own_calibration`, `_share_calibration`) sets it from each block's `Calib` line, then a block **without** one takes the correction of the other blocks of its `Region.sample` when they all agree (a wide scan next to calibrated core levels; per-level corrections that differ are not shared). `Region.energy` stays the file's raw axis: `Workspace._display` adds `Annotations.shift_for(fid, sample, name, r.calibration_shift)` — the user's own shift wins by scope, otherwise the file's — and marks the copy with `shift_applied`. Every reader of the shift (`_display`, `_marker_shift`, `_binding_at`, `htmlbrowser`, `apply_metadata`) passes the default; `shift_for(..., None)` tells "user set none" from zero. **Export round trip:** the copy carries hν + shift, so `export_vamas` writes hν − `calibration_shift` and a `Calib` line (`casafit.calib_line`, with the `Regions Comps` flags so a fit stays in the raw frame) when the block has none, so re-reading applies the correction once. `calibration.casa_statement` / `Workspace._casa_calibrations` add the sentence to the methods text; the metadata row is "BE calibration (CasaXPS)".
- **`elements.py`** / **`reels.py`** / **`iss_ui.py`** — ISS and REELS. `elements`: `ELEMENTS` (Z, most-abundant-isotope mass, name; the table of the author's XPSView project), `ION_MASS`, `kinematic_factor` (E1/E0 = [(cos θ + √(A² − sin²θ))/(1 + A)]²; None when a lighter target cannot scatter that far — for θ ≥ 90° that means A < 1), `iss_energy`, `iss_table`, `candidates` (window ±(0.5 % E0 + 2 eV), nearest first), `mass_from_energy` (bisection), `parse_symbols`, `marks_for`; tests check the 180° and 90° closed forms. `reels`: `elastic_peak`, `loss_axis`, `baseline` (median between the elastic tail and the lower pick, else the minimum), `band_gap(loss, y, p1, p2)` (tangent through two picks ∩ baseline, None unless the edge rises and the gap is positive), `tangent_points`. Stored in `Annotations`: peak markers may carry `kin: True` (a kinetic energy: not moved by the BE shift, drawn as hν − KE on a binding axis; `plots.draw_stack(markers=)` takes `(value, text[, kin])`, the HTML payload and `viewer.js` honour the flag) and `Annotations.reels` (region key → `{elastic, p1, p2, gap, base, slope}`, applied to the metadata as `REELS band gap (eV)`). `plots.draw_reels` overlays the construction on single-spectrum panels (`draw_stack(..., reels=)`, scaled by the panel's normalisation). `iss_ui.IssReelsDialog` uses `Workspace._click_cb` like Identify, and the helpers `spectrum_regions`, `kinetic_from_event`, `data_from_event`, `click_panel_spectra`, `reels_get/reels_set`; it refuses clicks on panels that show several spectra.
- **`appinfo.py`** / **`splash.py`** / **`about_ui.py`** — the app's identity and first impression. `appinfo` (Tk-free): `NAME`, `VERSION`, `GITHUB_URL` (the profile), `image_path(kind)` (looks for the user's `assets/splash.*`, and an optional smaller `about.*`, which falls back to the splash), `version_report()` / `library_versions()` (never raise). `splash.begin(argv)` is the **first thing `spectradeck.py` does when run as a script** (guarded by `__name__ == "__main__"`, so importing it in tests opens nothing): registers the fonts, makes the **one** Tk root (`TkinterDnD.Tk` when installed), withdraws it and shows the borderless splash as its Toplevel *before* the matplotlib / readers imports; `splash.status(...)` updates the line under the picture (no-op without one); `main()` takes the root back with `take_root()`, builds `Workspace`, and `finish(root)` deiconifies at once (so `_restore_layout` sees a mapped window) and destroys the splash after `MIN_SECONDS`. One root matters: `SwatchCache` and others create `PhotoImage`s with no master. Off with `--no-splash` or `cfg["show_splash"]` (Help menu). A missing or unreadable picture gives a text-only card. `set_window_icon` shrinks the picture for `iconphoto`; `set_app_id` gives Windows a taskbar identity. `AboutDialog` shows `small_picture` (≤ 220 px), name, version, the link (`open_link`), library versions, the IBM Plex credit and *Copy version info*.
- **`ribbon.py`** / **`icons.py`** — the tabbed toolbar replacing the old Open / Export / PDF strip. `ribbon.PAGES` is **data** (`(label, icon, target, tip, needs_data)`, dropdowns `("v", label, icon, items, tip, needs)`, `@theme` / `@pane` specials); a target is a `Workspace` method name or `(name, arg, ...)`, so `tests/test_ribbon.py` checks every target exists **and is still in `_build_menu`** (buttons are shortcuts; nothing may live only on them). `Ribbon` keeps the tab and fold state in `cfg["ribbon_tab"]` / `["ribbon_collapsed"]`, dims `needs_data` buttons while `app.docs` is empty (`Workspace._ribbon_state`, called from `_populate_tree`) and re-applies icons on `set_theme`. Styles `Ribbon.TFrame` / `Ribbon.TButton` / `Ribbon.Toolbutton` / `Tab.Toolbutton` are in `themes._style_clam`. `icons.py` draws ~30 line icons with Pillow on a 24-unit grid at 8x (`ICONS` registry, `draw(name, size, colour, accent)`); `IconCache(palette, size, master)` returns `ImageTk` images (rebuilt in `set_theme`, size scaled by `tk scaling`); `resolve_colour` turns Tk names such as the System theme's `systemwindowtext` into hex. Without Pillow the buttons are text-only. To add a button: an icon function in `icons.py` (decorated `@icon`), an entry in `PAGES`, the method in the menu.
- **`themes.py`** — the design tokens: six palettes (`Light` default, `Dark`, `Midnight`, `Solarized Light`, `High contrast`, `System` = native ttk theme), each with chrome colours, plot colours and a colour-blind-safe data palette (`cycle`); WCAG `contrast`/`luminance`, `ramp` (one-hue fade for long stacks), `mpl_rc` (open-frame plots, type scale), `SwatchCache` (tree tick boxes) and `scale_colourmap` / `scale_colours` (user-selectable colour scales; traces are trimmed/nudged to keep contrast ≥ 2 on the plot background) and `with_axis_colour` (frame/tick/label colour override, falls back when contrast < 3), `ThemeManager` (all non-System themes use ttk `clam`). **`fonts.py`** registers the bundled IBM Plex Sans per-OS via ctypes before `tk.Tk()`, applies it to Tk's named fonts and matplotlib, and falls back silently to the system font. **`pdf_preview.py`** — `PdfPreview` frame (PyMuPDF → PPM → `tk.PhotoImage`).
- **`Workspace`** (in `spectradeck.py`) — the single window: Tree | plot | info column in a horizontal `PanedWindow`; the centre is a container that swaps between the plot pane and the `PdfPreview`.
  - **Ticks vs selection:** ticking drives the plot, row *selection* drives Details/Images/Stage map. Ticks are a set of `id(region)` (`Workspace.checked`) so they survive tree rebuilds (filter, theme change, adding/removing files). Tick boxes are `PhotoImage`s on the Treeview rows; a click counts only when `identify_element` reports `"image"`. Redraws go through `_schedule_render` (`after_idle`).
  - **Grouping/stacking:** `group_regions` (by name, ≥50 % x-range overlap, or name per sample / per file) → one panel per group; the pure drawing functions live in `plots.py` (`draw_stack`, `draw_heatmap`, `draw_waterfall3d`, `add_ke_axis`, `norm_factor`, `trace_label`; re-exported by `spectradeck`, so `ee.draw_stack` etc. still work); `draw_stack` draws one spectrum plain or several stacked with an offset and optional normalisation. `view_var` switches each panel to `draw_heatmap` (pcolormesh + colour bar, `heat` ramp per palette) or `draw_waterfall3d` (mplot3d); non-Stack views z-sort each group in `_groups`. `scale_var` / `ke_var` choose the x axis (`add_ke_axis` adds the mirrored top axis); "At cursor" cursors are always stored as binding energy.
  - **View window:** `panels_var` (panels per page) + `panel_start` (row-aligned), `traces_var` + `trace_start` (window over long stacks); wheel / Shift+wheel / scrollbar / slider all just move those two and re-render. Only the visible panels and traces are drawn.
  - **Multiple files:** `Workspace.docs` is a list of readers; `region_parser` maps `id(region)` → its reader (needed for metadata, positions, images, export). `Region.source` labels traces when more than one file is loaded.
  - **Colour = file/sample, tree = legend:** `colour_slots` (one slot per file when several are loaded, else per sample) and `stack_colours` (categorical, or a ramp when a stack shares one slot) are pure functions; `_assign_colours` stores each ticked region's colour in `trace_color`, and `_refresh_boxes` draws that colour as the tree swatch, so tree and plot always agree. `draw_stack` puts end-of-trace labels in a right gutter (`dodge` keeps them apart; the gutter is reserved in `_draw_page`, not by `tight_layout`) and replaces y-ticks on stacks with a scale bar.
  - **Chrome:** one view row (group, normalise, offset), a contextual footer (panels/traces selectors; the scrollbar and trace slider are only packed when they can act, via `_layout_bottom`), a status bar for counts, `Tooltip` for hints, and an info column whose Images / Stage-map notebook only exists when the loaded files have images or positions (`_refresh_info`). The matplotlib toolbar keeps Back/Forward enabled because Windows paints disabled image buttons in the system grey.
  - **Theme:** `set_theme` re-applies ttk styles, rebuilds tick-box images and the tree, recreates the matplotlib toolbar (its icons are recoloured), and updates `matplotlib.rcParams`; PDFs are always drawn inside `rc_context(mpl_rc(PRINT))`.
  - Settings persist in `~/.spectradeck_config.json` (`load_config`/`save_config`); camera calibration in `~/.spectradeck_calib.json` (the files of the former name `~/.escape_explorer_*.json` are read until the first save).

## Verifying a reader

Readers are validated against **the same data in another format**, never by eye: a text export next to a binary file (`.vgd` ↔ `.avg`), or a vendor's own VAMAS export (`.spe`, `.kal`, `.avg` ↔ `.vms`). Compare energy arrays, counts (allowing documented factors such as dwell time or transmission), hν, pass energy, dwell and positions. Beware that a partner export can itself be wrong (a Casa VAMAS of the Scienta `.txt` has a reversed axis) — check physics (peak positions) before "fixing" a reader to match it. To exercise the GUI without instrument files, monkeypatch `EscapeParser.load` (or a reader's `load`) to fill `regions` and call `_build_tree()` on synthetic `Region`s.

## Roadmap (ideas taken from XPSView, `D:\Temp\xpsview`)

Work is split into milestones that are each tested and committed on their own; check in with the user before starting the next one (A–E are done). Principle for all of them: **user edits live in `annotations.py` beside the data and are applied on the way out — never mutate what a reader returns.** A CLI batch mode was deliberately left out for now. Quantification (at %) was left out until milestone F, which adds it from the CasaXPS fits (`quant.py`) to the HTML browser first (fits, quantification tab, depth profile, element ID, package cache; a desktop quantification view and report page are the next step).

- **Milestone A — done:** annotations overlay (display names, notes, editable metadata), BE calibration with a report statement, cursor read-out, element ID on surveys (`xpslines.py`), recent files, optional drag-and-drop, progress + cancel when loading, play/step through traces, *Save plot image…*, and the drawing functions moved to `plots.py`.
- **Milestone B — done:** `plotstyle.py` / `plotstyle_ui.py` (declarative `FIELDS` → dialog, presets, screen + PDF/PPT figure pages + PNG/SVG export, config + workbook state + each figure) and `holder.py` (live flip/nudge/rotate/spread calibration, click a marker to select the sample, halo'd labelled markers that dodge each other, calibration stored per workbook).
